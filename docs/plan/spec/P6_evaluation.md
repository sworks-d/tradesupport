# P6 評価・学習 — フェーズ設計＋タスク設計

**フェーズの役割**：提案（decision）の「予測 vs 実績」を評価し、Track Record と人間主導A/Bロジック育成に回す。
**全体ゴール寄与**：判断の質を実績で測り、明らかにダメなロジックを脱落させる（過信しない）。
**前からの引き継ぎ**：P5の記録（decision＋発注/保有）＋時間経過（評価期日）。**次への引き渡し**：
評価指標（命中率/超過リターン/シャープ等）→ロジック改善（A/B）→次サイクルのMAGIへ。
**フェーズのハルシネ防止方針**：R1 実績は実価格から算出／R4 評価未到来は pending（捏造しない）／A/Bは人間承認のGitコミットで残す。

### P6-1 decision評価ジョブ  〔✅ 先読み回避・冪等・P6-b〕
- 全体ゴール：提案の的中/外れを実データで判定。
- 前からの引き継ぎ：decision（target_period・entry）＋評価期日到来。
- 目的：評価日に実価格を取得し actual_return・hit/miss を計算・保存。
- 実装：評価ジョブ＋`models/decisions`(actual_return/hit_or_miss/evaluated_at)。価格は market_data。
- 次への引き渡し：評価済み decision（→P6-2 Track Record, P6-3 A/B）。
- ハルシネ防止：R1 実績は実価格のみ／R4 未到来は pending のまま（前倒し評価しない）。
- 受入：期日後に hit/miss が付く。

### P6-2 Track Record 実データ化  〔✅ R-mult/命中率/超過＋価格バックテスト／UI描画は未〕
- 全体ゴール：UIの予測の検証を実績に。
- 前からの引き継ぎ：評価済み decision群（P6-1）。
- 目的：命中率/平均リターン/S&P比超過/累積をUIへ（**スコア相関は廃止＝総合スコア無し**）。
- 実装：集計→snapshot→UI Track Record（旧前提のスコア相関は撤去＝D-19）。
- 次への引き渡し：評価指標（→P6-3, U表示）。
- ハルシネ防止：R1 実績集計のみ／総合スコア相関を出さない。
- 受入：実 decision の hit/miss がUIに反映、スコア相関欄は撤去。

### P6-3 A/Bロジック育成  〔❌ 枠のみ〕
- 全体ゴール：各審判の算定ロジックを人間主導A/Bで鍛える（自己改変は不採用）。
- 前からの引き継ぎ：評価指標（P6-2）＋複数世代のロジック。
- 目的：A/Bを並走→アウトオブサンプルで優劣→人間が勝者を選ぶ→Git管理。
- 実装：ロジックをパラメータ/関数として版管理。判定はシャープ/最大DD/命中率を併用。
- 次への引き渡し：採用ロジック（→P3審判へ反映）。
- ハルシネ防止：R5/原則7 改変主体は人間・判定基準は実績・合成は論理説明を関門に・世代はGitコミットで残す。
- 受入：データ蓄積後に2ロジックを実績比較し人間が選べる枠が動く（Phase後半）。
