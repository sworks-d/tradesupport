# U UI反映（横断）— 設計＋タスク設計

**役割**：各Pの出力を、収束先 `new_dashboard.html` のUIに「狂いなく」反映する。
**全体ゴール寄与**：人間が5秒で俯瞰し、詳細で決裁できる画面を提供（判断の律速はUIの質）。
**前からの引き継ぎ**：各Pの出力（snapshot.json）。**次への引き渡し**：一覧/詳細/決裁の表示・操作。
**ハルシネ防止方針**：UIは数値を作らない（snapshotの値を表示するだけ）／総合スコアは出さない（D-06/19）／
未照合・割れは決裁既定「保留」を視覚化（R6）。

> 状態：✅ / 🟡 / ❌ ／ コード：`ui/`（Next.js）、反映：`ui/app/LiveData.tsx`、生成：`scripts/build_snapshot.py`

### U-1 反映機構（Back→snapshot→UI）  〔✅〕
- 全体ゴール：バックエンド成果を画面に出す経路。
- 前からの引き継ぎ：各P出力。
- 目的：`build_snapshot.py` が `ui/public/data/snapshot.json` を生成→`LiveData.tsx` がDOMへ反映。
- 次への引き渡し：UI表示（一覧ミニ/GENDO/サイジング/検証フラグ/碇/保有/接続状態）。
- ハルシネ防止：UIは snapshot の値を表示するのみ（独自計算しない）。
- 受入：snapshot更新→再読込で画面反映（実NVDA・¥1M口座で確認済）。

### U-2 コンポーネント化＋視覚回帰  〔❌〕
- 全体ゴール：保守可能なUI＋「狂いなく再現」の保証。
- 前からの引き継ぎ：逐語移植済みの生HTML（dangerouslySetInnerHTML）。
- 目的：パネル単位でReactコンポーネント化（DOM/クラス逐語維持）＋Playwright視覚回帰（差分≈0ゲート）。
- 実装：`ui/app/` 分割＋Playwright。1コンポーネント移植毎に回帰。
- 次への引き渡し：コンポーネント化UI（→動的候補リスト表示=B3の複数候補に対応）。
- ハルシネ防止：（UI整合）視覚回帰で意図しない変化を検出。
- 受入：全画面でスクショ差分が閾値内。スコア痕跡撤去はC1（D-19・要再確認）。

### U-3 新規6画面  〔❌〕
- 全体ゴール：ダッシュボード以外の画面（収束先に実体が無い）を同トンマナで新規。
- 前からの引き継ぎ：各P出力＋トンマナ（既存CSS）。
- 目的：スクリーニング/ポートフォリオ/週次レポート/設定3種（戦略/口座連携/エージェント）。
- 実装：Next.jsルーティング＋画面（D-18：MVP後）。
- 次への引き渡し：各機能画面。
- ハルシネ防止：表示は各Pのデータのみ／総合スコア無し。
- 受入：各画面が同トンマナで実装・データ結線。

### U-4 接続状態・誤認防止表示  〔✅〕
- 全体ゴール：サンプルか実口座かを誤認させない（実弾判断の安全）。
- 前からの引き継ぎ：snapshot（broker/holdings_source/mode）。
- 目的：`.sb-live` に保有ソース（サンプル/moomoo）、`.sb-last-updated` に価格ソース(live/demo)を正直表示。
- 次への引き渡し：—（表示）。
- ハルシネ防止：実データとサンプルを明確に区別（誤認防止＝本プロジェクトの安全要件）。
- 受入：サンプル時は警告色「サンプル」、実口座時は「moomoo」（実装済）。
