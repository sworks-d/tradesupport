## 未決定（着手前に詰める）

### D-10 BALTHASAR（株価審判）のモデル ✅（2026-05-22 確定／推奨採用）
- **確定**：**コード計算（RSI/MACD等は既存technicalsを流用）＋LLMは解釈役のみ**。理由＝原則「数値はコードのみ」に最も整合。
- **影響**：B1（モデル割当）・B2（BALTHASAR実装）。

### D-11 確信度（confidence）の表現 ✅（2026-05-22 確定／推奨採用）
- **確定**：**定性ラベル（高/中/低）**。内部に数値を持っても UI には段階で出す。理由＝数値化はラバースタンプ化・疑似スコア化を招く。
- **影響**：B2・UI（judge_verdict表示）。

### D-12 2ソース照合の許容誤差 ✅（暫定確定・B1で調整可）
- **暫定**：株価は **±0.5%**（取得タイミングずれ吸収）。超過でフラグ。B1の実データで調整。
- **影響**：B1（2ソース照合）・B3（数値照合の赤判定基準）。

### D-13 割れ方の類型 ✅（暫定確定・B4で拡張可）
- **暫定**：doc の **4類型（一致／業績◯株価✕／株価◯業績✕／文脈✕）で開始**。運用で不足なら拡張。
- **影響**：B4（統合機構）・UI（`.magi-mini-state` / `.mf-state`）。

### D-14 第1信用性フィルタの実装範囲 ✅（2026-05-22 確定／推奨採用）
- **確定**：**段階導入**。先＝上場廃止基準/特設注意。後＝監査意見/GC注記/有報訂正。理由＝EDINET整備コストを抑えつつ最大リスクを先に潰す。
- **影響**：B1。

### D-15 碇発言「MAGI準拠」の機械判定ロジック ⏳（B5で設計）
- **論点**：碇の主張が judge_verdict 範囲内かをコードでどう照合するか。
- **方針**：実装設計事項。B5で具体化（碇発言中の各主張・数値を judge_verdict の reason/source_refs と突合し、範囲外を `gendo_compliant=false`）。製品分岐ではないためB5に委ねる。
- **影響**：B5（gendo_compliant）・UI（`.magi-flag` 碇MAGI準拠）。

### D-16 F0：HTML実装済み画面の範囲 ✅（2026-05-22 確定）
- **論点**：`new_dashboard.html` 内でスクリーニング/ポートフォリオ/週次/設定が実装済みか、ナビのみか。
- **確定（精査結果）**：実装済みは **ダッシュボード1枚＋詳細パネル4枚のみ**。ナビ切替JSは存在しない。
  - 再現対象＝サイドバー／アクションゾーン(売り・買い)／アラート＋インフォ／保有`.hold`×5／予測の検証(Track Record)／手動投入／トピックス／詳細パネル(`nvda`/`sell-7203`/`sell-tsla`/`laser`)。
  - **中身なし（ナビのみ）**＝スクリーニング・ポートフォリオ・週次レポート・設定3種（戦略/口座連携/エージェント）。「銘柄詳細」は詳細パネルが実体。
- **影響**：F0/F2 の対象が確定。残り6画面は D-18 へ。

### D-18 ナビのみ画面（収束先なし）の扱い ✅（2026-05-22 確定）
- **論点**：スクリーニング/ポートフォリオ/週次レポート/設定3種は `new_dashboard.html` に**実体がない**＝「狂いなく再現」できない。どうするか。
- **確定**：**MVPはダッシュボード＋詳細パネルに限定**（＝再現対象のみ）。残り6画面は MVP後、同トンマナで**新規デザイン**（ver1 §5.6 の段階実装に対応／F5）。再現と新規設計を混同しない。
- **影響**：UIトラックのスコープ。F2は再現対象のみ、新規6画面はF5。

### D-17 「クリーンでない情報」の主たる意図 ✅（2026-05-22 確定／案ア採用）
- **確定**：**不正企業の除外を主・情報源信頼度を従**。理由＝実弾運用で最も致命的なのは不正企業への投資（ゼロ化）。情報源の質はCASPERの割れ検出＋人間決裁が後段の保険。
- **影響**：B1（第1/第2フィルタを厚く）・CASPER入力の信頼度は従。

### D-19 「狂いなく再現」と SCORE: NONE の衝突 ✅（2026-05-22 確定／F0で発覚）
- **論点**：モックには総合スコア痕跡が**表示されたまま残る**＝「総合スコアを出さない」原則に違反。逐語再現すると違反ごと再現する。
  - 残存箇所：詳細パネルヘッダ「○○スコア X/100」**全4枚**（4014/4240/4389/4538）／more-listの`.mini-act-score`（8件超）／Track Recordの「スコア相関 0.62」／topic-impactの「スコア76」表記。
  - 補足：`.act-score`（アクションカードの大スコア）CSSは**markup未使用の死蔵コード**＝ダッシュボードのカードは既にGENDOのみで原則準拠。
- **確定（UIを勝手に変えない）**：
  1. **F1/F2は UI を一切変えない**＝モック完全一致で逐語再現し、視覚回帰の基準を確立。スコア痕跡もこの段階では残す。
  2. **唯一の UI 変更＝C1のスコア撤去**は、適用前に**ユーザーへ再確認（UI変更ゲート）**してから実施し、再ベースライン。
  3. ユーザー承認がない限りスコア痕跡は残ったまま（原則適合より UI不変を一時優先し、最後に承認の上で適合させる）。
- **影響**：F1/F2（UI不変・基準にスコア含む）・C1（撤去は再確認後・再ベースライン）。

### D-21 外部OSSの借用方針  ✅（2026-05-23 確定）
- **確定**：**自前実装が基本**。外部OSS（ai-hedge-fund / TradingAgents / FINSABER 等）からは
  **「考え方・ロジック」だけを借りて自前で実装する。コードの直輸入はしない。**
  - 借りる例：評価指標の考え方（Sharpe/最大DD/α・過大評価を避ける検証思想）、財務分析の観点
    （投資家流派が見る指標体系）、反証の組み立て方、reflection（参照提示）の発想。
  - 借りない：彼らのコードそのもの／LLM数値生成／自動執行／合意収束／自己改変。
- **理由**：コードを輸入しない＝ライセンス問題がほぼ消える（考え方は縛れない）。悪い癖（LLM数値生成等）を
  持ち込まない。**速度より深さ**（構築に時間をかけてよい）。
- **運用**：着想元は敬意としてコメント/ADRに記録（"〇〇の考え方を参考に自前実装"）。
- **影響**：C-0ライセンスゲートは「直輸入しない」前提で大幅に軽くなる（出典記録は残す）。X1/IMPROVEMENT_PLAN の借用線引きを本方針で上書き。
