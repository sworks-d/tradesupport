★ 外部AIエージェント投資リポジトリの活用＝北極星確定（2026-05-26 D-24）

DECISIONS.md D-24 で確定：claude-trading-skills を設計北極星とする。詳細仕様 = docs/plan/spec/X2_claude_trading_skills_adoption.md。

1. 借用候補リポジトリ（D-24 で再ランキング）

  • tradermonty/claude-trading-skills（★北極星★・MIT）：55スキル・8カテゴリ・5公式ワークフロー。
    "Decision-process OS / Plan → Trade → Record → Review → Improve"＝memory「持ち続けさせる機・Core-Satellite規律監督」と完全整合。
    X-2A〜D で5モジュール翻案（thesis_store / holding_health / exposure_coach / postmortem / performance_coach）。
  • edinetdb/dexter-jp（JP特化・要確認）：EDINET+J-Quants 自律エージェント。tradesupport は既に EDINET 使用＝直接相性。MAGI BALTHASAR（出典照合）の実装パターン参考。
  • okikusan-public/stock_skills（守り系のみ採用）：
    守り系（value_trap / shareholder_yield / 複利シミュ / concentration HHI）→ MAGI 車線。 攻め系（16プリセット探索／0-100スコア／Grok生成見通し）→ 不採用。
  • virattt/ai-hedge-fund：投資家ペルソナ分析／バックテスト評価指標 → P6 補強候補
  • TradingAgents：多エージェント議論(debate)・reflection 構造 → MAGI 統合機構の「割れ表示」と P6-2/3 補強

2. 構造案：二車線アーキテクチャ（ZEELE × MAGI）

探索（攻め）と決裁（守り）を別車線に分け出力経路を分離。車線間のゲートは「人間が watchlist へ昇格」だけ。

  • ZEELE車線（発議・探索）：stock_skills攻め系を移植。LLMが数値を出してよい／スコア・予測歓迎／出力は「候補プール＋物語」止まり、決裁ラインへ直結禁止
  • 真実車線：moomoo＋yfinance の2ソース照合（来歴メタ source_refs／data_asof 必須）
  • MAGI車線（判断・決裁）：3審判→防御層→統合→碇司令→人間決裁。SCORE: NONE、数値はコードのみ。stock_skills守り系を移植

3. 漏出防止の規律（UIで強制）

  • ZEELE出力は別ゾーン・別配色・「参考／未照合」バッジ常時表示
  • ZEELE→decisions の直接FK禁止。watchlist 経由でのみ流入（コードで強制）
  • MAGIプロンプトに ZEELE 出力を入力しない（審判の独立性原則の延長）
  • サンセット条項：6ヶ月毎にZEELE発議銘柄の1年後リターン vs ベンチマーク評価 → 勝てなければ車線ごと廃止

  • X-2A：thesis_store（最優先・B0〜B6 並走可）— Trader Memory Core 翻案。投資テーゼライフサイクル管理
  • X-2B：holding_health — Kanchi T1-T5 翻案。EDINET 統合済 tradesupport で直接実装可
  • X-2C：exposure_coach — 既存 market_analyst の SCORE:NONE 違反箇所を解体・再構成
  • X-2D：postmortem + performance_coach（ペーパー運用後）— P6 評価・学習の実装層
  • 並走で stock_skills 守り系（value_trap／株主還元利回り／複利シミュ／HHI）を MAGI 車線に取り込み
