# 📋 朝の確認用：論点リスト

夜間作業中に「あなたの判断が必要 / 確認が必要」な論点を整理しました。**急ぎは A 〜 C のみ**、それ以外はあとで OK。

## A. すぐに判断が欲しい論点（次の議論で扱う）

### A-1. 利確スコアの「シナリオ達成度」の判定をどうやるか
**論点**：「当初の仮説（thesis）が達成されたか」を AI に判定させる際、何を入力に与えるか。
- **案1**：thesis テキスト + 最新の財務データ + 最新のニュース → LLM 判定（コスト高、解釈ブレやすい）
- **案2**：thesis を「**達成条件のチェックリスト**」として保存し、各項目を機械的に判定
- **案3**：ハイブリッド（チェックリスト形式の thesis + 補助的に LLM で総合判定）

**私の推奨は案3**。買い時に「達成条件 3〜5項目」を thesis として登録 → 朝バッチで各項目を機械判定 + LLM で総合解釈。

### A-2. screening の Universe（候補母集団）の決め方
**論点**：日本株 3,800社 + 米国株 8,000社、全部を毎朝スクリーニングしないので、母集団をどう絞るか。
- **案1**：時価総額上位 N 社（例：米国S&P500 + TOPIX500）
- **案2**：流動性しきい値（出来高・売買代金）でフィルタ
- **案3**：ユーザーが「興味リスト」を持って、その中でスクリーニング

**私の推奨は案1+2の組み合わせ**。時価総額上位500 + 流動性しきい値クリア = 約500-700社。これでAPIコストも抑えられる。

### A-3. 「目標期間」を誰が決めるか
**論点**：「中期 3ヶ月」「長期 1年」のような目標期間を、誰が・いつ決めるか。
- **案1**：AI が買いレコメンド時に自動決定（戦略カテゴリベース）
- **案2**：ユーザーが採用時に手動入力
- **案3**：戦略カテゴリ別のデフォルト（V字回復=3ヶ月、テーマ=6ヶ月、長期=1年）+ ユーザーが調整可能

**私の推奨は案3**。デフォルト値を AI が提示 → ユーザーが採用時に承認/調整。これが一番現実的。

## B. 利確 / 損切りの方針（昨晩任せられた件）

### B-1. 利確の半量売却を選択肢化 vs 全量強制
- **採用：選択肢化**（推奨どおり）
- 理由：利確は「もう少し伸びるかも」の余地があるため、ユーザーに選ばせるべき
- 「強く推奨（90+）」のみ全量推奨、「推奨（70-89）」は半量を初期選択肢に

### B-2. 損切りは常に全量強制
- **採用：全量強制**（推奨どおり）
- 理由：損切りは規律、迷う余地を作らない。FX で「感情に振られた経験」を踏まえた設計
- 「明日まで様子見」のボタンは残すが、これは「**先延ばし**」ではなく「**24時間後に再判定**」として明示

# C-1.1 保有銘柄カード

## 1. パネルの役割

保有している銘柄を **3カラムグリッド** で表示し、**各銘柄が当初の仮説どおりに進捗しているか** を一目で判断できるようにする。

### このパネルが解決する問題
- 含み損益だけ見て一喜一憂する状況を防ぐ（**仮説の進捗で評価する**）
- 各銘柄の目標期間と残り日数を可視化（**売却タイミングの予期に使う**）
- 状態（順調 / 注視 / 危険 / 利確圏）を色で即時識別

### 設計の核心
**「実時間ではなく、戦略時間で銘柄を見る」**

例：
- AAPL は買って 39日経過、長期1年戦略なので **「まだ 10% の進捗、326日残り」**
- 7203 は買って 33日経過、中期6週間戦略なので **「もう 78% の進捗、9日しかない」**

実時間で見ると AAPL の方が長く保有しているが、戦略時間で見ると **7203 のほうが緊急**。これが従来の保有資産ツールで見えなかった視点。

## 3. 計算ロジック

### 3.1 含み損益

```
含み損益額 = (current_price - buy_price) × qty
含み損益率 = (current_price - buy_price) / buy_price
```

通貨換算は最終表示時のみ（JPY 換算は表示レイヤーで）。

### 3.2 進捗（経過日数 / 目標期間）

```
elapsed_days = today - buy_date
progress = elapsed_days / target_period_days  (0.0〜1.0+)
remaining_days = target_period_days - elapsed_days
```

`progress > 1.0` の場合（目標期間超過）は **後述の特殊ハンドリング**。

### 3.3 状態判定（4つの状態）

以下の順に評価、最初に該当した状態を採用：

```
1. 利確圏（status_profit）
   if 含み損益率 >= target_pct × 0.85 AND progress >= 0.5
   → 「目標到達寸前」または「目標達成」
   → 売り推奨カード（利確）に同じ銘柄が出る

2. 危険（status_danger）
   if 含み損益率 <= stop_loss_pct × 0.95
      OR scenario_status == "broken"
   → 「損切りライン接近」または「シナリオ崩壊」
   → 売り推奨カード（損切り）に同じ銘柄が出る

3. 注視（status_warn）
   if 含み損益率 < (期待された progress 時点の予測値) - 5pt
      OR scenario_status == "weakening"
   → 「予測から下方乖離」「シナリオ弱体化」

4. 順調（status_good）
   上記いずれにも該当しない
```

【たたき台】しきい値（0.85、0.95、5pt）は実運用で調整。Phase 1 は仮設定で出してみて、感触で調整する想定。

### 3.4 シナリオ進捗の予測値

各時点での「予測された含み損益率」は、線形補間で算出：

```
expected_return_at_progress(p) = target_pct × p × 1.0
（単純線形補間：progress=0.5 のとき target_pct の半分）
```

【たたき台】より精緻には、銘柄ごとの予測曲線を持つべきだが、Phase 1 は線形でOK。

### 3.5 「残り日数」の表示ルール

| progress | 表示 |
|---|---|
| 0.0〜0.5 | `残り XXX日` |
| 0.5〜0.85 | `残り XX日` |
| 0.85〜1.0 | `残り X日 · 目標到達寸前` |
| 1.0〜1.2 | `目標期間超過 · 判断要` |
| 1.2+ | `目標期間 +XX日超 · 強く判断要` |

### 3.6 グラフ描画用データの生成

各保有銘柄について、以下の点列を朝バッチで生成・永続化：

```
graph_data = [
  past:    [(date, return_pct), ...]   # 取得日〜今日まで毎日1点
  future:  [(date, predicted_return_pct), ...]  # 今日〜目標日まで予測
  target_line: target_pct
  loss_cut_line: stop_loss_pct  # 危険銘柄のみ表示
]
```

#### past（実績）
- buy_date から today まで、各取引日の終値を取得
- return_pct = (price - buy_price) / buy_price

#### future（予測）
- today から target_date まで、目標達成までの予測ライン
- 単純線形補間で OK：`pred(d) = current_return + (target_pct - current_return) × ((d - today) / remaining_days)`
- 状態によって**予測の傾き**を変える：
  - 順調：線形補間でtarget_pct へ向かう
  - 注視：線形補間だが目標到達は遅れ気味（target_pct × 0.7 で到達想定）
  - 危険：下振れシナリオ（target_pct ではなく stop_loss_pct へ向かう）
  - 利確圏：横ばい（追加上昇余地なし）

#### 予測の不確実性帯（上下のレンジ）
- 上限：pred + (現在のボラティリティ × √(remaining_days))
- 下限：pred - (現在のボラティリティ × √(remaining_days))
- 【たたき台】ボラティリティは過去30日の標準偏差を使う

## 4. 表示ルール

### 4.1 並び順

以下の優先順位で降順：

1. **状態の緊急度**：危険 > 利確圏 > 注視 > 順調
2. **進捗 progress**：高い順
3. **取得日**：新しい順

これにより、**最も判断が急がれる銘柄が左上**に来る。

### 4.2 表示要素

各カードに表示するもの（既に dashboard.html で実装済み、ここでは仕様として再定義）：

| 戦略バッジ | "中期 · 3ヶ月" / "長期 · 1年" 等 | 最上部 |
| カテゴリバッジ | "US 半導体" / "JP 自動車" 等 | 最上部 |

### 4.4 ハイライト条件

- 「**売り推奨**」と表示された銘柄は、**同時に売り推奨カードにも表示される**ことを明示

## 5. エッジケース

### 5.1 データなし

- **保有銘柄が0件**：「保有銘柄はまだありません」プレースホルダー + 「買い推奨から選ぶ →」のリンク
- **portfolio はあるが price が取得できない**：価格欄を `--` 表示、グラフは過去のみ表示

### 5.2 目標期間超過（progress > 1.0）

- 自動で「危険」状態に格上げ（追加の判断が必要）
- グラフ：右端が画面外になる代わりに、現在地が右にはみ出さないよう調整（描画的には目標期間を超過しても X 軸を伸ばす）
- 状態ラベル：「**目標期間超過 · 判断要**」

### 5.3 仮説（thesis）が空

- 「仮説：（未設定）」と表示
- 設定画面で編集できることを示唆（Phase 1 では編集機能は別途）

### 5.4 通貨が混在する場合

- 各銘柄カードは元通貨で表示（USD は $、JPY は ¥）
- 含み損益額の表示は元通貨
- サイドバーの「総資産」は全て JPY 換算（為替変換）

### 5.5 buy_date が当日

- progress は 0%
- グラフの過去部分は1点のみ（取得点）
- 「保有 1日目」と表示

# C-1.2 売り推奨カード（利確 / 損切り）

## 1. パネルの役割

保有銘柄のうち、**今日〜数日内に売却判断が必要な銘柄** をピックアップして表示。

### このパネルが解決する問題
- 「売り時を逃す」「損切りができない」という投資の典型的な失敗を防ぐ
- 機械的な判断を促す UI（感情に振られた経験を踏まえた設計）
- 「**利確**」と「**損切り**」を明確に区別する

### 設計の核心
**「売却スコア」という単一指標で判断を機械化**

スコア 70 以上 = 推奨、それ未満 = 注視（または無視）。
スコアの内訳を詳細パネルで開示することで、ブラックボックス化を回避。

## 3. 計算ロジック

### 3.1 利確スコア（profit_taking_score）の算出

4つの軸を 0〜100 で評価し、加重平均：

| 軸 | 評価項目 | 重み |
|---|---|---|
| **目標達成度** | 現在のリターン / 目標リターン | 40% |
| **シナリオ達成度** | 当初の仮説が実現したか | 30% |
| **テクニカル悪化** | RSI、出来高、ローソク足パターン | 20% |
| **AI の確信度** | LLM 判断の確信度 | 10% |

```
profit_taking_score = (
  target_achievement * 0.4 +
  scenario_achievement * 0.3 +
  technical_warning * 0.2 +
  ai_confidence * 0.1
) * 100
```

#### 各軸の算出
- **target_achievement**：`min(current_return / target_pct, 1.0)`
- **scenario_achievement**：sell-recommender エージェントの判定（後述）
- **technical_warning**：以下の合成
  - RSI > 70：+0.4
  - 5日連続上ヒゲ：+0.3
  - 出来高減少（20日平均比 -20%以下）：+0.3
- **ai_confidence**：LLM プロンプトで「この銘柄を売るべき確信度（0-1）」を要求

【たたき台】重み 4:3:2:1 は仮設定。Phase 1 で4週間運用してから調整。

### 3.2 損切りスコア（stop_loss_score）の算出

同じく4軸：

| 軸 | 評価項目 | 重み |
|---|---|---|
| **シナリオ崩壊度** | 当初の仮説が実現しなかった度 | 35% |
| **損失幅** | 現在のリターン / 損切りライン | 30% |
| **ニュース・IR の悪化** | 関連トピックスのネガティブ度 | 20% |
| **AI の確信度** | LLM 判断の確信度 | 15% |

```
stop_loss_score = (
  scenario_break * 0.35 +
  loss_magnitude * 0.3 +
  negative_news * 0.2 +
  ai_confidence * 0.15
) * 100
```

#### 各軸の算出
- **scenario_break**：sell-recommender エージェントの判定（仮説の達成度の**逆**）
- **loss_magnitude**：`min(abs(current_return) / abs(stop_loss_pct), 1.0)`
  - 例：現在 -7.8%、損切りライン -8% → 0.975
- **negative_news**：直近7日のネガティブニュース件数 × 重要度
- **ai_confidence**：LLM プロンプトで「この銘柄を切るべき確信度」

### 3.3 スコアによる分類

| スコア | 分類 | 表示場所 |
|---|---|---|
| **90 以上** | 強く推奨 | 売り推奨カードの主役（最上部） |
| **70-89** | 推奨 | 売り推奨カードの主役 |
| **50-69** | 注視 | 「他の注視銘柄」リスト |
| **50 未満** | 表示しない | （保有銘柄カードのみ表示） |

【たたき台】しきい値は仮設定。スコアが現実的かどうかは Phase 1 で検証。

### 3.4 利確 vs 損切り の判定

同じ銘柄で両方のスコアが出ることはほぼないが、両方70以上の場合：
- **含み損益率 > 0** なら利確を優先表示
- **含み損益率 < 0** なら損切りを優先表示

通常は含み損益で自動的にどちらかに分岐するため、衝突は稀。

### 3.5 推奨売却数量の決定

| 状況 | 推奨数量 |
|---|---|
| 利確 · 強く推奨（90+） | 全量売却 |
| 利確 · 推奨（70-89） | **半分売却** |
| 損切り · 強く推奨（90+） | 全量売却 |
| 損切り · 推奨（70-89） | 全量売却 |

利確の場合のみ「半分売却」という選択肢を出す。**残り半分で追加上昇を狙う**ためで、これは投資の定石。
損切りは中途半端な売却が傷を広げるため、常に全量。

### 3.6 売却指値の決定

#### 利確の場合
- 現在価格 -0.3%（やや低めの指値で確実に売る）
- 【たたき台】数値は実運用で調整

#### 損切りの場合
- 成行（指値ではない、すぐ売る）
- 【Claude Code 判断】 moomoo の成行注文の正確な API 仕様で実装

# C-1.3 買い推奨カード

## 1. パネルの役割

スクリーニング・分析を経た **新規買いの候補銘柄** をピックアップして表示。

### このパネルが解決する問題
- 「何を買うべきか分からない」を解消（**スコア順に推奨を提示**）
- 「機会捕捉」と「過剰な売買」のバランス（**スコア閾値で件数を絞る**）
- 「シナリオ思考」を促す（**強気/ベース/弱気の3シナリオを必ず提示**）

### 設計の核心
**「総合スコア」と「3シナリオ」の組み合わせ**

スコアだけでは「どれくらい儲かるか」が見えない。シナリオだけでは「どれくらい確からしいか」が見えない。**両方を提示することで、ユーザーは確率加重で判断できる**。

## 3. 計算ロジック

### 3.1 総合買いスコアの算出

**5軸**で評価、加重平均：

| 軸 | 評価項目 | 重み |
|---|---|---|
| **ファンダメンタル** | EPS成長、PER水準、業界比較 | 30% |
| **テクニカル** | トレンド、RSI、出来高、サポート | 20% |
| **ニュース・センチメント** | 直近7日のポジネガ、IR動向 | 15% |
| **戦略適合性** | V字 / テーマスコア | 25% |
| **AI 確信度** | LLM 総合判断 | 10% |

```
total_score = (
  fundamental * 0.30 +
  technical * 0.20 +
  news_sentiment * 0.15 +
  strategy_fit * 0.25 +
  ai_confidence * 0.10
) * 100
```

【たたき台】重みは仮設定。Phase 1 で4週間後にスコア × 実績で相関を見て調整。

### 3.2 スコアによる分類

| スコア | 分類 | 表示場所 |
|---|---|---|
| **80 以上** | 強く推奨 | 買い推奨カードの主役（最大2件）|
| **65-79** | 推奨 | 主役の続き or 「他の候補」リスト |
| **50-64** | 候補 | 「他の候補」リスト |
| **50 未満** | 表示しない | スクリーニング画面でのみ閲覧可 |

【たたき台】売りより閾値を下げてある（売りは70、買いは65）。理由：**買い逃しのコストは「待つ」だけ、売り逃しは「損失拡大」**。買いは慎重に。

### 3.3 3シナリオの算出

各銘柄について、3シナリオを必ず生成：

| シナリオ | 算出方法 | 表示 |
|---|---|---|
| **強気（bull）** | ベースケース × 1.5〜2.0 | "+42% 30%" |
| **ベース（base）** | LLM が判断した最尤シナリオ | "+27% 50%"（**太線**）|
| **弱気（bear）** | ベースケース × -0.3〜-0.5 | "-9% 20%" |

確率は LLM が判断するが、**合計 100% になるように正規化**。

#### 期待リターン（確率加重平均）

```
expected_return = (bull_return × bull_prob) + (base_return × base_prob) + (bear_return × bear_prob)
```

例：(42% × 0.3) + (27% × 0.5) + (-9% × 0.2) = 12.6% + 13.5% - 1.8% = **+24.3%**

これが「期待リターン」として詳細パネルに表示される。

### 3.4 推奨エントリー価格の決定

| 戦略カテゴリ | エントリー方針 |
|---|---|
| 中期V字 | 現在価格 -1.5% の指値（押し目買い） |
| 中期テーマ | 現在価格 -0.5% の指値（軽い指値）|
| 長期 | 成行（タイミングより銘柄選定が重要） |

【たたき台】数値は仮。「エントリーの遅れ vs 約定失敗」のバランスで調整。

### 3.5 推奨投資額の決定

```
recommended_amount = min(
  available_cash * 0.20,    # 1銘柄あたり現金の最大20%（リスク管理）
  total_assets * 0.10,      # 1銘柄あたり総資産の最大10%
  推奨額_by_score            # スコア80+ なら高め、70-79 なら控えめ
)
```

`推奨額_by_score`:
- スコア 90+ → 上限まで
- スコア 80-89 → 上限の80%
- スコア 70-79 → 上限の60%
- スコア 65-69 → 上限の40%

最小ロット（米国株は1株、日本株は100株等）に合わせて切り下げ。

### 3.6 thesis_checklist の生成

例（NVDA）：
```
- [ ] データセンター売上が次Q +20% 以上
- [ ] AMD MI325 の市場シェアが 15% 未満に留まる
- [ ] 中国規制が現状維持（強化なし）
- [ ] 株価が $98.50 の指値内で約定
```

これが **保有後の進捗判定**（C-1.1 のシナリオ進捗）に使われる。

# C-1.4 サイドバー（総資産・配分・サマリー）

## 1. パネルの役割

**ツール全体のサマリーパネル** として、ナビゲーション以上の情報集約機能を持つ。
ユーザーが朝開いた瞬間に **「資産はどうなっている / 今日何件のアクションがある」** を把握できる。

### このパネルが解決する問題
- 「自分の総資産がいくらか」を即座に把握
- 「今日のアクション件数」を一目で把握（売り買い・警告）
- 「API コスト消化状況」を把握（予算管理）
- 配分を **Core-Satellite** で管理（横棒バー）

## 3. 計算ロジック

### 3.1 総資産の集計

```
total_assets_jpy = (
  sum(米国株 current_price × qty × USD_JPY_rate) +
  sum(日本株 current_price × qty) +
  cash_jpy
)
```

USD_JPY_rate は moomoo の為替レート、または補助 API（毎朝バッチで取得）。

### 3.2 今日の変化

```
change_today_jpy = total_assets_jpy_now - total_assets_jpy_at_market_open_today
change_today_pct = change_today_jpy / total_assets_jpy_at_market_open_today
```

「市場開始時点」は **米国 5:30 / 日本 9:00** のスナップショットを保存しておく。

### 3.3 累計リターン（30日）

```
cumulative_30d_pct = (total_assets_now - total_assets_30d_ago) / total_assets_30d_ago
cumulative_30d_jpy = total_assets_now - total_assets_30d_ago
```

日次スナップショットを保存（後述の portfolio_snapshots テーブル）。

### 3.4 配分の算出

```
配分の4分類：
1. 米国株 = sum(米国株 holdings 価値) / total_assets
2. 日本株 = sum(日本株 holdings 価値) / total_assets
3. サテライト = sum(strategy_category in ["長期", "短期"] holdings) / total_assets
4. 現金 = cash_jpy / total_assets
```

【たたき台】「サテライト」は strategy_category で判定。Phase 1 は実質ゼロかもしれないが、枠として残す。

### 3.5 今日のサマリー集計

```
売り推奨件数 = count(sell_signals where score >= 70 and created_at = today)
買い推奨件数 = count(buy_signals where score >= 65 and created_at = today)
警告件数 = count(portfolio where status == "status_warn") + count(other warnings)
的中率_30d = sum(decisions where hit == true and date >= 30d_ago) / sum(decisions where date >= 30d_ago)
```

### 3.6 月次コストの計算

```
month_cost_jpy = sum(cost_logs where date in current_month)
month_budget = settings.monthly_budget_jpy  # デフォルト ¥5,000
month_consumption_ratio = month_cost_jpy / month_budget
```

予算超過時の挙動：
- 80% 到達：黄色警告
- 100% 到達：**朝バッチを停止**（settings.budget_breach_action = "halt" の場合）

### 3.7 portfolio_snapshots テーブル（日次集計）

毎日終値後（米国市場引け後 = JST 6:00頃）にスナップショット：

| カラム | 型 | 説明 |
|---|---|---|
| date | date | 主キー |
| total_assets_jpy | float | |
| cash_jpy | float | |
| us_stocks_value_jpy | float | |
| jp_stocks_value_jpy | float | |
| satellite_value_jpy | float | |
| usd_jpy_rate | float | スナップショット時のレート |

これがあれば、30日推移グラフを描画できる。

# C-1.5 トピックスセクション

## 1. パネルの役割

朝バッチで AI が **読んだニュース・IR・X発言** を表示し、**判断の透明性** を確保する。

### このパネルが解決する問題
- 「AI が何を読んで判断したか」のブラックボックス化を回避
- ユーザーが追加情報を得るためのソース提示
- ニュースが各レコメンドにどう影響したかを明示（**影響表示**）

### 設計の核心
**「AI の判断の根拠を、ユーザーが追跡できるようにする」**

各トピックには：
- **重要度**（重要 / 中 / 低）
- **影響先銘柄**（オレンジでタグ）
- **影響テキスト**（"TSLA 損切り推奨の根拠の一つ"）
- **元ソースへのリンク**（外部リンク）

を持たせることで、ユーザーは AI の判断を「**追体験**」できる。

---

## 2. 入力データ

### topics テーブル
| カラム | 型 | 説明 |
|---|---|---|
| id | int | |
| collected_at | datetime | 収集時刻 |
| source | str | "Bloomberg" / "Reuters" / "EDINET" 等 |
| source_url | str | 元記事のURL |
| category | str | "macro" / "sector" / "stock" |
| importance | str | "high" / "medium" / "low" |
| headline | str | 見出し（AI 要約済み） |
| summary | str | 1-2行の要約（AI 生成） |
| original_text | str | 元のテキスト（参照用、表示はしない） |
| affected_tickers | list[str] | 影響先銘柄リスト |
| impact_text | str | "TSLA 損切り推奨の根拠の一つ" 等 |
| linked_decisions | list[int] | 紐付くレコメンド ID |
| created_at | datetime | |

---

## 3. 計算ロジック

### 3.1 ニュース収集（朝バッチ）

```
ソース：
- NewsAPI（米国 + 国際ニュース）
- 日経電子版 RSS
- Bloomberg RSS
- Reuters RSS
- TechCrunch RSS（テック特化）
- 9to5Mac RSS（Apple 特化）
- SEC EDGAR（重要IR）
- EDINET（日本IR）
- TDnet RSS（適時開示）
- 政府公式 RSS（FRB、財務省、ホワイトハウス等）
```

過去24時間以内に公開されたものをすべて収集 → 重複削除（headline類似度 + URL 一致でデデュープ）。

### 3.2 重要度の判定（ハイブリッド：ルール + AI）

#### ルールベース（一次フィルタ）
```
high:
  - SEC EDGAR の 8-K 重要IR
  - TDnet の決算速報
  - FRB / 日銀の利上げ・利下げ発表
  - 影響先銘柄が保有銘柄に含まれる

medium:
  - 業界全体に影響するニュース
  - 影響先銘柄が買い候補に含まれる

low:
  - 上記以外
```

#### AI 補強（二次判定）
ルールで「medium」「low」と判定されたものは LLM（Sonnet）でレビュー：
- 「このニュースは [保有銘柄リスト] [買い候補リスト] にどう影響するか」
- LLM が "重要" と判断したら格上げ

#### 最終判定
ルール > AI（衝突時はルールが勝つ）

【たたき台】重要度の判定基準は実運用で調整。「重要」が多すぎても少なすぎても困る。

### 3.3 影響先銘柄の自動紐付け

```
ステップ1：固有名詞抽出
- LLM（Ollama、Cold Path）で記事から固有名詞・ティッカー候補を抽出
- 例：「NVIDIA」「Tesla」「FSD」「Powell」

ステップ2：銘柄マッチング
- 抽出した固有名詞を universe テーブルとマッチング
- 一致：NVDA, TSLA をタグ付け

ステップ3：影響テキスト生成
- LLM（Sonnet、Hot Path）で「このニュースが [タグ付き銘柄] にどう影響するか」を生成
- 出力：「TSLA 損切り推奨の根拠の一つ・シナリオ崩壊を補強」
```

【Claude Code 判断】ステップ1のNER（Named Entity Recognition）は LLM 使うか spaCy 等のライブラリ使うかは実装者判断。

### 3.4 レコメンドとの紐付け

```
for topic in topics:
  for decision in today_decisions:
    if topic.affected_tickers contains decision.ticker:
      if topic.created_at within 7days of decision.created_at:
        topic.linked_decisions.append(decision.id)
        decision.supporting_topics.append(topic.id)
```

これにより、相互参照が可能：
- トピックスから「これはどのレコメンドに影響？」
- レコメンドから「これはどのトピックスに支えられている？」

# C-1.6 Track Record（予測の検証）

## 1. パネルの役割

過去のレコメンドの結果を集計し、**AI の信頼性** を可視化する。

### このパネルが解決する問題
- 「AI を信用していいのか」の疑念を、データで答える
- 「次のレコメンドはどれくらい確からしいか」の判断材料
- S&P500 との比較で「市場に勝てているか」を見る

### 設計の核心
**「AI の判断は確率的に正しい」を裏付けるデータ**

100% 当たることはあり得ない。だが、**70% 当たって平均 +5% のリターンを出している**と分かれば、ユーザーは AI を信頼できる。

---

## 2. 入力データ

### decisions テーブル
| カラム | 型 | 説明 |
|---|---|---|
| id | int | |
| date | date | レコメンド日 |
| ticker | str | |
| action | str | "buy" / "sell_profit" / "sell_loss" |
| score | int | レコメンド時のスコア |
| scenario | dict | 強気/ベース/弱気 |
| expected_return | float | 確率加重平均の期待リターン |
| target_period_days | int | |
| evaluation_date | date | 評価日（レコメンド + target_period） |
| actual_return | float | 実績リターン（評価日時点）|
| hit_or_miss | str | "hit" / "miss" / "pending" |
| user_action | str | "adopted" / "skipped" / "modified" |

### 評価ロジック

```
評価日（evaluation_date）になった decision について：
- adopted されたもの：実際の売却時点のリターン
- skipped されたもの：仮想的なリターン（採用していたら）
- 評価:
  - actual_return が expected_return × 0.7 以上 → "hit"
  - actual_return が 負 かつ -5% 以下 → "miss"
  - その他 → "neutral"（中間判定）
```

【たたき台】"hit" の基準は仮設定。「期待の70%」を超えたら的中とする緩めの設定。

---

## 3. 計算ロジック

### 3.1 統計4枚

```
的中率_30d = count(decisions where hit_or_miss == "hit" and date >= 30d_ago) /
             count(decisions where date >= 30d_ago and hit_or_miss != "pending")

平均リターン_30d = avg(decisions where date >= 30d_ago and hit_or_miss != "pending")

スコア相関 = pearson(scores, actual_returns)  # decisions の score と actual_return の相関

S&P500との差 = (avg(actual_returns) - S&P500_30d_return) / 過去30日
```

### 3.2 累積リターン推移グラフ

```
時系列で、各日の以下を計算：
- 実績の累積リターン（オレンジ実線）
- 予測の累積リターン（オレンジ点線）
- S&P500 の同期間リターン（ティール実線）

各点 = 個別レコメンド1件
色：的中 = 緑、外れ = 赤
```

### 3.3 スコア × リターンの散布図【Phase 2-】

STEP B で削除したが、AI の信頼性検証に重要。Phase 2 で詳細画面に復活させる。

# C-1.7 手動投入

## 1. パネルの役割

ユーザーが **X発言・記事URL・銘柄コード** などを投げ込んで、AI に即時解釈させる。

### このパネルが解決する問題
- 朝バッチで拾えない速報・トレンドへの対応
- 「これが投資判断に影響するか」を AI に聞ける
- X (Twitter) を公式 API なしで実質的に対応する

### 設計の核心
**「ユーザーの注意を、ツールに統合する」**

X で見たトランプ発言、ニュースサイトの記事、知人の SNS 投稿 — これらを **コピペするだけで AI が解釈** し、影響先銘柄を提示する。

---

## 2. 入力データ

### 動的入力（ユーザーから）
- テキスト：X発言、記事URL、ニュース見出し、銘柄コード、自由文
- 任意：銘柄コードを明示的に指定

### 参照データ
- portfolio（保有銘柄）
- universe（買い候補母集団）
- 直近のトピックス（既知情報との照合）

---

## 3. 計算ロジック

### 3.1 投入内容の自動分類

```
入力テキストを以下に分類：
- URL のみ → URL 取得 + 記事分析
- ティッカー（"NVDA", "7203" 等）→ 銘柄分析モード
- テキスト本文 → 直接分析（X発言等）
- URL + テキスト → URL 取得 + テキストも併用
```

### 3.2 分析の実行

```
1. 入力を LLM（Sonnet）に送る
2. プロンプト：
   - 「あなたの保有銘柄: [list]」
   - 「あなたの買い候補: [list]」
   - 「上記を踏まえて、この情報が投資判断にどう影響するか分析せよ」
3. LLM から以下を出力：
   - 影響先銘柄（自動抽出）
   - 影響の方向（ポジティブ / ネガティブ / 中立）
   - 影響の規模（大 / 中 / 小）
   - 推奨アクション（「TSLAの損切り推奨を強化」等）
```

### 3.3 結果の保存

```
manual_inputs テーブルに保存：
- input_text
- input_url（あれば）
- analyzed_at
- result（LLM 出力）
- affected_tickers
- llm_cost
```
