# 第1部：全体要件

## 1.1 プロジェクトの一言定義
moomoo OpenAPI を介して米国株・日本株の中期投資を、MAGI型マルチエージェントが支援する、ローカル完結の個人向けトレードアシスタント。完全個人利用。

## 1.2 不変の原則（これを破ると別物になる）
1. **主戦場は中期投資（Core-Satellite）。** マーケットタイミングで全戦略を切り替えない。
2. **判断はMAGI（3審判の独立検証）、推奨は碇司令、決裁は人間。** この3層を崩さない。
3. **MAGIは総合スコアを出さない。** 3審判を1点に統合しない（独立性の担保）。
4. **数値はコードが照合した実データのみ。LLMに数値生成させない。** ハルシネーション遮断の中核。
5. **Tier 1（手動発注）から始める。** 判断品質に確信が持てるまで自動売買しない。
6. **ハルシネーションは「ゼロ化」でなく「混入しても決裁前に検出・遮断」。**
7. **学習はA/Bロジック育成（人間主導）のみ。自己改変は不採用。**

## 1.3 目標と撤退ライン
| ライン | 値 |
|---|---|
| 運用元本 | 10万円 |
| 現実的成功 | 年率+30〜50% |
| 撤退 | 元本5万円割れ（-50%）で設計を根本見直し |
| 月次API予算 | 5,000円（運用元本とは別腹） |
| 日次API予算 | 500円（超過で全停止） |

## 1.4 アンチパターン（やらないこと）
マーケットタイミング運用／いきなり完全自動売買／X公式API直接利用／スクレイピングのコア組み込み／総合スコアでの銘柄要約／LLMによる数値計算・検算／自己改変型の学習。

# 第2部：オーケストレーター（処理の全体フロー）

## 2.1 投資判断ファネル
```
全市場
  → ① 定量スクリーニング（LLMなし・pandas/TA-Lib）
  → ② 信用性ハードフィルタ（粉飾・上場廃止基準・監査意見で除外）
  → ③ MAGI 3審判が独立審議（並列・互いを見ない）
  → ④ 防御層（コードが数値を独立照合・出典実在確認・時点照合）
  → ⑤ 統合機構（判断しない・割れ方を可視化・総合スコアを出さない）
  → ⑥ 碇司令（MAGIを読んで推奨＋反対論拠を生成）
  → ⑦ 人間が決裁（承認/否認/保留）
  → ⑧ Tier 1：発注リスト出力 → 手動発注（moomoo）→ 記録
```

## 2.2 MAGI 3審判（三権独立）
対等な3審判が、同じ銘柄を、互いの結論を見ずに、独立に「可否＋根拠＋確信度」を出す。誰も最後ではない。

| 審判 | 判断軸 | 入力ソース（独立） | モデル |
|---|---|---|---|
| MELCHIOR・1 | 業績（ファンダ） | 財務数値（EDINET/yfinance） | Ollama |
| BALTHASAR・2 | 株価（テクニカル） | 価格・出来高 | `[未確定]`（計算主体、LLMは解釈役か） |
| CASPER・3 | 文脈（イベント） | ニュース・適時開示（TDnet/NewsAPI） | Sonnet |

- 反証は専任エージェントを置かず、「割れること自体」が反対意見として機能する。
- 検算は審判でなく防御層のコードが機械的に行う。

## 2.3 統合機構（判断しない）
3審判の見解を並置し、割れ方を類型化するのみ。推奨・採点・決定はしない。
| 割れ方 | 表示する解釈（推奨はしない） |
|---|---|
| 3審判一致 | 確信度高。ただし「全員同方向に誤った可能性」も併記 |
| 業績◯・株価✕ | 業績は良いが株価の勢いなし。タイミング尚早の疑い |
| 株価◯・業績✕ | 株価は動くが業績裏付けなし。需給先行の疑い |
| 文脈✕ | 数字は良いが上昇の文脈なし／織り込み済みの疑い |

## 2.4 碇司令（推奨役・決定しない）
- MAGIの出力**だけ**を根拠に、推奨と反対論拠を**必ず両方**生成する。
- MAGIにない新事実を創作してはならない（防御層が「碇発言 MAGI準拠」を機械チェック）。
- 推奨は方向＋簡潔な理由。反対論拠は「反対するなら：」で必ず併記。

# 第5部：各パネルの役割（パネル別仕様）

> 物理ファイルは分けず、本セクションでパネル別に定義（連動の参照性のため）。

## 5.1 一覧カード（俯瞰・5秒で読む層）
- 役割：朝開いて「どの銘柄に注目すべきか」を一目で掴む。
- 左：GENDOインジケーター（碇アイコン＋日本語一語＋GENDOラベル）。横マージン広め・縦罫線で独立。固有名は出さず構えのみ。
- 中：ティッカー、市場タグ、サマリー、MAGIミニ（`MELCHIOR 業績 買` 形式＝**固有名主・役割従**）、割れ方。
- GENDO語彙：買い一致=推し / 買い割れ=要検討 / 利確=利確 / 損切り=撤退 / 保有継続=静観。命令形を避ける。
- スコア（旧84点）は**出さない**。
- クリックで詳細パネルへ。

## 5.2 詳細パネル（決裁・摩擦をかける層）
- 役割：1銘柄を吟味し決裁する。上から「事実→相談→検証→決断」。
- MAGI判定ゾーン：鼎立図（業/株/文ノード・ステータスで点灯/点線）＋3審判リスト（**役割主・固有名従** = 「業績」大、「MELCHIOR・1 / FUND」小）。
- フッタ：割れ方＋`SCORE: NONE`。
- 碇司令ゾーン：推奨＋「反対するなら：」＋根拠注記（MAGI準拠の宣言）。
- 検証＋決裁：フラグ3種（数値照合/信用性/碇MAGI準拠）＋ボタン（承認/否認/保留、文脈で色変化）＋「反対論拠を読んでから決裁」ヒント。未照合や割れがあれば既定を保留に。
- グラフ：既存の予測（買い）/予測vs実績（保有）を流用。CHART/MAGIのタブ切替は任意。予測値には未照合バッジ。
- フォント主従：一覧と詳細で逆（一覧=固有名主、詳細=役割主）。

## 5.3 サイドバー（現状把握）
- 既存流用：総資産＋スパークライン、配分（Core/Satellite/現金の横棒）、今日のサマリー、ナビ。判断と無関係なので大きく変えない。

## 5.4 保有銘柄パネル（Phase 2-）
- 役割：保有中銘柄の「購入時予測 vs 実際」を追跡。MAGIは「継続/利確/撤退」を判定。
- 詳細パネルは売り側（利確/損切り）の構造を流用。

## 5.5 手動投入パネル
- 役割：X代替。トレンド情報を人間が貼り、CASPER相当が即分析。速報性の担保。

## 5.6 その他画面（Phase 1-で段階実装）
スクリーニング／ポートフォリオ管理／週次レポート／過去レコメンド（Track Record）／設定（戦略パラメータ・リスク上限）。

# 第6部：状態・連動・エラー（補完項目）

## 6.1 状態遷移（パネルがいつ何を出すか）
```
審議中(pending) → 判定確定(judged) → 決裁待ち(awaiting) → 承認(approved)/否認(denied)/保留(held)
  → approved → 発注リスト出力(order_listed) → 手動発注済(ordered) → 保有(holding)
```
UIは status に応じて表示を変える（審議中はローディング、決裁待ちはボタン活性化等）。

## 6.2 決裁アクションの結果フロー
- 承認 → 発注リストに追加（Tier 1は自動発注しない）→ ユーザーがmoomooで手動発注 → 発注記録を入力/同期 → holding化。
- 否認/保留 → decision_logに理由とともに記録。保留は再審議キューへ。

## 6.3 検証フラグの判定ロジック（フラグを緑/赤にする基準）
- 数値全照合：judge_verdictの全source_refsが実データと一致 → 緑／1つでも未照合 → 赤＋unverified_claims表示。
- 信用性：第1フィルタ通過かつ第2フィルタ（CF乖離等）異常なし → 緑／異常あり → 警告。
- 碇MAGI準拠：commander_rec内の主張がjudge_verdictの範囲内 → 緑／範囲外の創作検出 → 赤。

## 6.4 エラー・欠損時のUI挙動（「分からないを正直に」のUI版）
- データ取得失敗：該当審判を「判定不能（データ欠損）」と表示。推測で埋めない。
- 審判が判定不能：その旨を明示し、碇は「3審判のうちXが判定不能。確信を持てない」と述べる。
- API停止/予算超過：パネル上部に停止バナー。新規審議を止める。

## 6.5 更新タイミング
- 朝バッチ（launchd, 6:00 JST想定）で全審議を更新。
- 手動更新ボタン（既存UIにあり）で個別/全体を再審議。コスト消費するため確認を挟む。
