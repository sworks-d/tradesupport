## 0. この差分の背景（なぜ追加するか）

`STEP_A_FINAL.md` の STEP C 論点リストには、以下が**抜けていた**：

- 信用性・粉飾フィルタ（クリーンでない銘柄・情報の除外）

これらは**この分野全体の未解決問題**であり、各プロジェクトが採る現実的対策は本プロジェクトの
既存構想（反証エージェント＋数値とLLMの分離＋人間の最終承認）と一致することが確認できた。
本差分は、その構想を実装仕様のレベルまで具体化したもの。

## 1. 思想の再定義（最重要・ここを外すと全部崩れる）

### 1.1 「ハルシネーション絶対禁止」→「混入しても押す前に検出・遮断」

LLMは確率的次トークン予測器であり、幻覚をゼロにすることは原理的に不可能。
研究でも、最も進んだ手法で幻覚率を 1% 程度に下げるのが限界（ゼロにはならない）。

したがってゴールを再定義する：

| Before（達成不能） | After（達成可能・実害を防ぐ） |
|---|---|
| ハルシネーションを発生させない | 発生しても、ハンコを押す前に検出・遮断する |

避けたいのは「幻覚が存在すること」ではなく「嘘の数字を信じて実弾を投じること」。
後者は構造で防げる。前者は防げない。

### 1.2 「粉飾は全部弾ける」→「発覚済みは弾く／進行中は警戒フラグ」

| 種類 | 例 | 対応 |
|---|---|---|
| A：発覚・係争中の不正 | 過去の不正会計、特設注意市場、監査意見が不適正 | **ハード除外**（入口で弾く） |
| B：未発覚・進行中の粉飾 | 発覚前の東芝・エンロン型 | **弾けない**。警戒フラグ＋分散で被害限定 |

種類Bは個人どころか監査法人でも見抜けない領域。完全防止は約束しない。

## 2. MAGI判断層＝三権独立（新規・rev.2で作り直し）

### 2.0 rev.1の誤りと訂正
rev.1は MELCHIOR→BALTHASAR→CASPER の**直列フロー**だった。これはMAGIではない。
- CASPERを「反証専任（前2者の結論を受けて反対する）」にした時点で、CASPERは下流に従属し独立性が崩れていた。
- 流れが一方向＝三権分立ではなく**三審制（一審→二審→三審の上訴構造）**になっていた。

訂正：MAGIの本質は**対等な3つが並列・独立に同じ案件を審議し、互いの結論を見ない**こと。
上下も前後もない。下記に作り直す。

### 2.1 目的
「複数の専門家が独立に審議し、主権者（人間）が決裁する」を実装する層。
全エージェントが同じClaudeだと同じ方向に間違えるため、独立性を構造で担保する。

独立性は2階層：
- **入力独立**：各審判が見るソースを物理的に分ける（解決可能）
- **モデル独立**：審判ごとに使うLLMを変える（緩和可能）

### 2.2 3審判＝対等な3パラダイム
反証を専任にすると独立性が壊れるため、3審判は**対等な3つの判断軸**にする。
3つとも同じ銘柄を、同時に、互いの結論を見ずに審議し、独立に「可否＋根拠＋確信度」を出す。誰も最後ではない。

| 審判 | 独立した判断軸 | ソース（入力独立） | モデル（モデル独立） |
|---|---|---|---|
| MELCHIOR | ファンダ（業績の実態） | 財務数値（EDINET/yfinance） | Ollama |
| BALTHASAR | テクニカル（株価の勢い・需給） | 価格・出来高 | 別モデル `[未確定]` |
| CASPER | 文脈・イベント（なぜ動くか） | ニュース・適時開示（TDnet/NewsAPI） | Sonnet |

### 2.3 反証と検算はどこへ行ったか（重要）
rev.1で専任エージェントにしていた「反証」「検算」は、審判から外し、**構造側**に移す：
- **反証**：3審判が割れること自体が反対意見として機能する（例：ファンダ◯・テクニカル✕なら既に異議が立っている）。専任を置かず、独立性から自然に立ち上げる。
- **検算**：審判の仕事ではなく、防御層（第3章・第5層）が**コードで機械的に**全数値を独立再取得して照合する。

### 2.4 統合機構＝判断しない（確定）
多数決は「割れた」という最重要情報を握り潰すため禁止。
さらに統合機構に「既定推奨」を持たせると、それに引っ張られてラバースタンプ化が再発する。
→ **統合機構は判断せず、集計と可視化に徹する。** 決定は主権者（あなた）。

統合機構がやること：3審判の独立見解を並置／割れ方を類型化／検証フラグを付す。やらないこと：推奨・採点・決定。

| 割れ方 | 解釈（可視化のみ。アクションは指定しない） |
|---|---|
| 3審判とも買い | 確信度高。ただし全員一致＝相関で同方向に誤った可能性も併記 |
| ファンダ◯・テクニカル✕ | 業績は良いが株価の勢いがない／下落中。タイミング尚早の疑い |
| テクニカル◯・ファンダ✕ | 株価は動くが業績裏付けなし。デッドキャットバウンス／需給先行の疑い |
| 文脈✕（CASPER） | 数字は良いが「なぜ上がるか」の文脈がない。または織り込み済み |

`[未確定]` 割れ方の類型はこれで足りるか。確信度の表現（数値スコア化 or 定性ラベル）をどうするか。

### 2.5 三権独立の代償（誠実な明記）
多数決という自動決着機構を捨てたため、**割れた案件はすべて主権者（あなた）が捌く**。
少数精鋭（5銘柄）だから回るが「楽になる」設計ではない。**あなたの判断力が律速**になる。
したがって統合機構の「割れ方を判断材料として整理する質」が生命線。ここが甘いと丸投げになる。

### 2.6 既存設計への書き換え
- `STEP_A_FINAL.md` の market-analyst を、この三権独立3審判に**置き換える**（収集層とは分離）。
- screening-agent は「収集・一次選抜」側に残す。MAGIはその後段の独立審議。
- Hot/Cold割当：MELCHIOR=Cold(Ollama)、CASPER=Hot(Sonnet)、BALTHASAR=モデル`[未確定]`。
- `[未確定]` BALTHASAR（テクニカル）のモデル。テクニカルは数値計算主体なのでロジックはコード、LLMは解釈役に留める可能性が高い。

## 3. ハルシネーション防御：5層（新規）

効く順。上ほど費用対効果が高い。

### 第1層：データと判断の分離（最優先・コストゼロ）
数値はコードがAPIから取得した実データのみ。LLMは「生成」ではなく「渡された数字を読む」役に限定。
研究の「決定論的ファクト台帳（deterministic fact ledger）」と同じ思想。
**既存設計（定量=pandas/TA-Lib、解釈=LLM）が既にこれ。崩さないことが最大の防御。**
実装注意：Claude Code が「便利だから」とLLMに数値処理させる箇所を、コードレビューで執拗に潰す。

### 第2層：出典の強制添付＋実在照合
LLMが事実を述べる時、出典（ファイルID・行・URL）を必須化。
**出典を付けさせるだけでは不十分**（研究：整備されたRAGでも引用を捏造する）。
→ その出典が実在し値が一致するかを**コードで照合**する。照合できない主張は自動却下。

### 第3層：MAGIの相互検証（2章の構造がそのまま効く）
- MELCHIORの数値とコード取得の実データが不一致 → 幻覚として自動フラグ
- 審判間で事実関係が矛盾（一方が増収前提、他方が減収前提）→ 片方が幻覚 → 警告
- 3審判が独立に同じ事実誤認をする確率は、入力・モデルを分けるほど下がる

### 第4層：「分からない」を許可・推奨（空欄を埋めさせない）
プロンプトで「データなし時は『データなし』と明記。推測での補完を禁止」を明示。
かつ「不明と正直に答えたエージェントを減点しない」評価設計にする。
埋める動機（役立たずと思われたくない圧力）を消す。

### 第5層：数値検算は審判でなくコードが担う（rev.2で修正）
rev.1はCASPERに検算させていたが、CASPERは独立審判になったので検算は外す。
→ 防御層のコードが、各審判の出した数字を別経路で取り直して機械照合。不一致でアラート。
LLMに検算させない（LLMは算術エンジンではない＝第1層の原則）。コストゼロ。

### 時点ラベルの強制（V字回復に直結・必須）
研究で確認された temporal hallucination（「Q1の数字」を「Q2」と取り違える）対策。
V字は「いつの四半期に反転したか」が生命線。全数値に「いつ時点か」を必須添付し照合。
決裁シートに「数値の時点」を必ず表示。

### 学術的重武装は採用しない（個人には過剰）
ファインチューニング、モデル内部回路の操作（Liar Circuits等）、商用幻覚検出プラットフォームは
コスト・データ整備の面で月5,000円・個人運用に合わない。設計思想だけ借りる。

## 4. 信用性フィルタ：2段階（新規・収集層に追加）

### 第1フィルタ：ハード除外（種類A・機械的に弾く）
スクリーニング最初期で、以下を候補に入れる前に物理除外：
- 監査意見が「無限定適正」以外（限定付き・意見不表明）
- 上場廃止基準への抵触、特設注意市場銘柄
- 過去N年以内の有報の重大な訂正
- 継続企業の前提に関する注記（ゴーイングコンサーン注記）あり

取得元：EDINET 開示データ。
`[未確定]` Phase 1で全部やるか、重大なもの（上場廃止・特設注意）だけ先に機械化し監査意見は段階導入か。

### 第2フィルタ：ソフト警戒（種類B・弾かずにフラグ）
粉飾に頻出する異常パターンを検出したら、除外せず決裁シートに警戒フラグ：
- 利益は出ているのに営業キャッシュフローがマイナス（最大の危険信号）
- 売上増なのに売掛金が異常に膨張
- 在庫が売上の伸び以上に積み上がる
- 利益率が同業比で不自然に高い

除外でなくフラグにする理由：正当な理由で一時的にこうなる健全企業も多く、機械的除外は優良V字候補も捨てるため。
この異常パターン検出はコードで機械的に行い、決裁シートのフラグに反映する（審判の仕事にしない）。

### 残るリスクの受容
種類Bは完全には防げない。最後の保険は**分散**（1銘柄20%上限）。1社が粉飾でも全資産は飛ばない。

`[未確定]` 「クリーンでない情報」の主たる意図が「不正企業の除外」か「信頼できない情報源の除外」か。
比重で第1/第2フィルタの設計とニュースソース信頼度スコアの重みが変わる。要確認。

## 5. 決裁シート仕様（新規・UI・rev.2修正）

ハンコを押す瞬間に1銘柄ごとに表示する項目。動線で「ラバースタンプ化」を防ぐ。

1. **3審判の独立見解を並置**（ファンダ／テクニカル／文脈、各々の可否・根拠・確信度）
2. **割れ方の可視化**（2.4の類型。統合機構は推奨を出さない＝ここに「買え」は書かれない）
3. **反対材料**（割れた審判の見解そのものが反対意見。専任の異議ではなく、独立見解の不一致を提示）※割れている場合、その内容を読まないと押せない動線
4. **ハルシネーション検査結果**（全数値が実データ照合済みか／未照合の主張を赤字ハイライト／各数値の時点）
5. **信用性フラグ**（第2フィルタの警戒シグナル）
6. **決裁ボタン**（承認/否認/保留）※未照合項目 or 審判が割れている場合は既定を「保留」に
7. **質問インターフェース**（各審判に追加質問）

設計原則：意志の力で気をつけるのではなく、**動線で強制する**（③を物理的に通過させてから⑥）。
統合機構が推奨を出さないため、決裁シートは「答え」ではなく「判断材料」を提示する。決めるのは主権者。

## 6. A/Bロジック育成（新規・rev.2で差し替え／自己成長は不採用）

### 6.0 自己成長は採用しない（確定）
AIが自分でプロンプト/skillを書き換える自己成長は**却下**。報酬ハッキングと静かな劣化で全安全装置を内側から壊すため。

### 6.1 採用するもの：人間主導のA/Bロジック育成
各審判の中の**算定ロジック**を、A/Bで比較し、良い方を人間が選んで育てる。
自己成長との決定的な違い：
- **改変の主体は人間**（AIは書き換えない。人間が2つのロジックを定義し、勝者を選ぶ）
- **判定基準はデータ（実績）**（思いつきでなく、運用実績で優劣を測る）

例：MELCHIOR（ファンダ審判）の業績反転判定を、A（営業利益の連続改善で見る）と B（売上＋利益率の複合で見る）で並走させ、良い方を採用 → 次は A vs A''（Aの改良版）でさらに洗練。世代を重ねる。

### 6.2 構造（三権独立）とは別レイヤー
A/Bは**各審判の中身（算定ロジック）を鍛える**話。審判の数・独立性・三権構造そのものは変えない。
構造（三権独立）と中身洗練（A/B）は別レイヤーなので両立する。

### 6.3 A/Bの罠（前回潰した報酬ハッキングが形を変えて潜む）
1. **「良い方」をリターン単体で測ると運を実力と誤認する。** → シャープレシオ・最大DD・勝率・命中率を併用（既存の評価指標を流用）。
2. **安易な合成は過剰適合を生む。** AとBの良いとこ取りで合成すると過去にだけ当てはまるフランケンシュタインになる。合成時は「なぜ効くか論理的に説明できるか」を必須の関門にする。説明できない合成は不採用。
3. **世代を重ねるほど過去への過剰適合が累積する。** A→A'→A''と同じ過去データで選び続けると過去専用機になる。

### 6.4 罠を避ける設計（投資ロジック開発の定石）
- 勝敗は複数指標で測る（特にシャープレシオで運と実力をある程度分離）
- 評価は**学習に使っていない期間のデータ**で行う（アウトオブサンプル検証）。過去を期間で割り、前半で作り後半で検証。
- 統合は勝者総取りか合成かを毎回人間が判断。合成は論理説明を関門に。
- 世代（A/A'/A''）はGit管理。劣化したら戻せる。**人間の承認付きコミットとして残る**点が自己成長と決定的に違う。

### 6.5 期待値の調整（誠実な明記）
個人規模（10万・5銘柄・数ヶ月）では、統計的に有意なA/B判定に**相当の時間がかかる**。
数銘柄では運と実力が分離できるサンプルが集まらない。
→ 「科学的に最適化する」より**「明らかにダメなロジックを脱落させる」程度の期待値**が現実的。過信は禁物。

### 6.6 順序
データが溜まって初めて優劣を測れる。Phase 0でデータゼロの今は回すものがない。
**枠だけ本書に残し、実装はデータが蓄積する Phase 1後半〜Phase 2。**

## 8. 実装順序（重要・一気にやらない）

1. **第1層（数値とLLMの分離）の徹底** — 既存設計の死守。コストゼロ・効果最大。
2. **三権独立を Claude単体・入力だけ分離の3審判** から始める（モデルは後で分ける）。まず独立審議と統合機構の可視化が回ることを確認。
3. 動いたら **モデル分離**（Ollama他）を足す。
4. **信用性フィルタ第1（ハード除外）** を収集層に追加。
5. **決裁シート**のUI実装（統合機構は推奨を出さない＝判断材料の提示に徹する）。
