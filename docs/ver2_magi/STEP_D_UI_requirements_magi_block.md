# UI要件定義：MAGI決裁ブロック（既存dashboard.htmlへの追加）

作成日：2026-05-22
位置づけ：`STEP_C_DELTA_judgment_layer.md`（判断層設計）を、既存 `dashboard.html` のUIに落とす発注書。code側（Claude Code）への実装指示。
前提：UIは既存HTMLが唯一の真実。本書は「既存に何を足すか」の差分発注。

> この発注書は「何を作るか」だけでなく「なぜそうか（設計思想）」「実装で壊してはいけない点」を含む。
> 思想を省くとAIが曲解する（例：V字回復を勝手に解釈する問題と同根）。各仕様に理由を付す。

---

## 0. 大前提（ここを外すと全部無意味になる）

- 既存 `dashboard.html` のトンマナ（ダーク・洗練された実務ツール）を維持する。エヴァ風の原色・装飾は**不採用**（一度試したが既存UIから浮いたため却下）。
- MAGI決裁ブロックは、既存の銘柄カードを開いた先の**詳細パネルに挿入**する想定。一覧カードは別途（本書末尾の未確定参照）。
- 既存のグラフ（予測・予測vs実績）は**そのまま流用**。MAGIブロックはそれに追加する形。

---

## 1. このブロックが体現する設計思想（実装者は必読）

1. **MAGIは事実認定のみ。総合スコアを出さない。** 3審判の見解を統合して1つの点数にしてはいけない。理由：三権独立（対等な3審が独立判断）の思想。単一スコアは「統合してないのに統合したフリ」で嘘になり、ユーザーの思考停止（ラバースタンプ化）を招く。画面に `SCORE: NONE` と明示する。
2. **碇司令は推奨するが決定しない。** 推奨と同時に必ず反対論拠を併記する。理由：パートナーが一方的に背中を押すと判断代行になる。両面提示で「考えさせる」役に留める。
3. **決裁はユーザー（人間）。** 承認/否認/保留ボタンはユーザーが押す。碇の推奨は判断材料であって決定ではない。
4. **数値はコードが照合した実データのみ。予測値（モデル生成）は事実と区別して表示。** ハルシネーション遮断の中核。予測グラフには「未照合（参考）」バッジを付け、碇の推奨根拠から除外する。

---

## 2. ブロック構造（上から下への情報の流れ）

縦に「事実 → 相談 → 検証 → 決断」が流れる1枚のカード。

```
┌─ カードヘッダ ──────────────────────┐
│ NVDA  [US 半導体タグ]      [MAGI 263] │
├─ MAGI判定ゾーン ───────────────────┤
│ [鼎立図]  MELCHIOR・1  買い  根拠文   │
│           BALTHASAR・2  買い  根拠文   │
│           CASPER・3     慎重  根拠文   │
├─ MAGIフッタ ───────────────────────┤
│ 2/3買い・全会一致せず      SCORE: NONE │
├─ 碇司令ゾーン ─────────────────────┤
│ (碇)司令 / 判断アシスト                │
│ 推奨文（買い…）                        │
│ │反対するなら：…（反対論拠ボックス）   │
│ 根拠：3審判の判定のみ…                 │
├─ 検証フラグ＋決裁 ──────────────────┤
│ [数値 全照合済][信用性 問題なし][碇発言 MAGI準拠] │
│ [承認して発注へ] [否認] [保留]         │
│ CASPERの反対論拠を読んでから決裁…      │
└──────────────────────────────────┘
```

予測グラフは「予測グラフ」タブとして MAGI判定ゾーンと切替（既存グラフを流用、未照合バッジ付き）。

---

## 3. 鼎立図（MAGIの3審判を図で表現）

- 中心（MAGIコア）から3方向に結線、3審判を六角ノードで配置。
- **ノードは審判の識別と判定ステータスを同時に表す**（装飾ではない・重要）：
  - 識別：色（MELCHIOR=キーオレンジ #ff8c42 / BALTHASAR=サブティール #4ecdc4 / CASPER=警告イエロー #fbbf24）
  - ステータス：買い=塗りつぶし点灯、慎重/見送り=点線・半輝（opacity 0.45）
  - ノード内に略号 M / B / C
- 図の下に圧縮キャプション（例「M買 B買 / C慎重 2-1で割れ」）。
- 役割分担：図＝一目で全体像（速読）、右の3行リスト＝各審判の根拠（精読）。重複ではなく速読/精読の二段。

---

## 4. 3審判リスト（各行）

各行の構成：色タグ（左の細いバー）｜審判名＋英字サブ｜判定｜根拠文

- 判定の色は**意味ベースで統一**：買い=緑(--up #4ade80)、慎重=黄(--warn #fbbf24)、見送り=赤(--down #f87171)。
  - 注意：審判の識別色（タグ）と判定の良し悪し色（文字）は**役割を分離**する。MELCHIORのタグが赤系でも、判定が買いなら文字は緑。混同させない。
- 根拠文には実データ照合済みの旨を含める（例「反転は営業利益ベース（照合済）」）。

---

## 5. MAGIフッタ
- 割れ方を提示（例「2/3買い・全会一致せず」）。**多数決の結論は出さない**（「だから買い」とは書かない）。
- 右端に `SCORE: NONE`（総合スコアを出さない思想の明示）。

---

## 6. 碇司令ゾーン
- アバター（碇）＋「碇司令」＋「判断アシスト」。
- 推奨文：方向＋簡潔な理由（例「私の推奨は買い（小さめに入る）。MELCHIORの営業利益反転を重く見る」）。
- 反対論拠ボックス：左罫線(--warn)で区切り、「反対するなら：」で始める。**必ず併記**（省略不可）。
- 末尾に根拠注記：「3審判の判定のみ。新たな事実は加えていない。予測グラフの数値は推奨の根拠にしていない」。
  - これは碇のハルシネーション防止の宣言。碇がMAGI出力外の事実を創作していないことを示す。

---

## 7. 検証フラグ＋決裁
- フラグ（サブティール背景）：「数値 全照合済（時点明記）」「信用性 問題なし/警戒」「碇発言 MAGI準拠」。
  - 未照合の数値があれば該当フラグを警告色にし、決裁ボタンの既定を「保留」にする。
- 決裁ボタン：承認して発注へ（主・キーオレンジ）／否認／保留。
- ヒント：「CASPERの反対論拠を読んでから決裁してください」。動線で熟慮を促す。

---

## 8. フォント仕様（環境依存で壊れやすい・要注意）

**確定方針：**
- ゴシック（既定）：`'Noto Sans JP', 'Inter', sans-serif` — NVDA、タグ、判定、根拠文、フラグ、ボタン、ヒント、フッタ等すべて。
- 明朝（例外3箇所のみ）：`'Noto Serif JP', serif` — ①3審判名（MELCHIOR・1等）②「碇司令」の名前③碇の発言本文（推奨文＋反対論拠）。
- 数値・英字ラベル（CODE、FUNDAMENTALS等）：`'JetBrains Mono', monospace`。

**実装で必ず守ること（モック検証で判明した罠）：**
1. **両日本語フォント（Noto Sans JP / Noto Serif JP）を必ず明示的に読み込む**（Google Fonts等）。読み込まないと環境のフォールバックで意図しない書体（特に全面明朝化）になる。
2. **ゴシック要素はフォント未指定の継承任せにしない。** 親の継承に頼ると、セリフ環境でフォールバックして全部明朝になる（実際にモックで発生）。ゴシックを明示指定し、明朝は3箇所だけ上書きする構造にする。
3. フォントの最終確認は実装環境で行う（モック環境はフォント事情が異なり当てにならない）。

## 9. 配色トークン（既存HTMLから踏襲・新規作成しない）

```
--bg:#0d0d11 --bg-1:#14141a --bg-2:#1c1c24 --bg-3:#25252f
--border:#2a2a35 --border-2:#3a3a48
--ink:#ece9de --ink-2:#a09d92 --ink-3:#6b6962
--key:#ff8c42（オレンジ・主）--sub:#4ecdc4（ティール）
--up:#4ade80 --down:#f87171 --warn:#fbbf24
角丸 --r:10px --r-lg:14px
```
新しい色を勝手に足さない。MAGIの審判色も上記の既存トークンの割当で済ませる。

## 10. 実装上の技術注意
- タブ切替（MAGI判定/予測グラフ）：既存がNext.js想定なら、表示/非表示はReactのstateで管理（モックの素のJSをそのまま移植しない）。
- 予測グラフは既存HTMLのSVGを流用。未照合バッジだけ追加。
- 保有銘柄の決裁（売り/利確/損切り）では、タブ内のグラフが「予測vs実績」に変わる。構造同じ・中身違い。
