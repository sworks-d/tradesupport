🔄 データフロー（1 日次バッチ）

1
候補発掘: MAGI が業績スクリーニング → Gendo stance（推し/要検討/静観）
ZEELE がテーマニュースから別ルートで候補追加（preset 付き）
2
候補プール構築: MAGI + ZEELE の和集合 → CandidatePool
_build_candidate_pool: stance × preset × source を保持
3
AKAGI Brief 構築: 各銘柄に対し yfinance / news / peer / events を取得 → 5 中立スコア生成
technicals は MAGI 借用 → yfinance フォールバック / news は辞書 → Haiku（env有効時）
4
DS 自発 proposal: REI/ASUKA/SHINJI は select_from_pool（自分の accept_stances）
KAWORU は select_kaworu_contrarian（他機が選ばなかった銘柄で短期エッジ）
5
KATSURAGI 優先度補正: 各 proposal に AKAGI Brief の boost を加算（戦略プリセット重み）
priority = base_confidence + ritsuko_boost × 0.5
6
例外判定 + 排他制御: 決算前 7 日 / ピア最下位 / Sonnet 強い売りをブロック
同銘柄に複数機 proposal なら priority 最高のみ採用
7
予算配分 + 安全装置チェック: 機別需要 × 重み → per_pilot_jpy
HALT / 市場 -3% / 1 命令上限 / 1 機上限 を順次適用
8
paper_exec で fill: Stop-loss / time exit / 機内重複防止 → Portfolio に記録
moomoo_sim で手数料・スリッページ・FX 反映
9
UI 更新: build_snapshot.py で snapshot.json 再生成 → React が fetch
5 分自動 / 手動ボタンでも実行

📌 設計思想
・責任分離: 発掘（MAGI/ZEELE）/ 調査（AKAGI）/ 判断（KATSURAGI）/ 執行（DS）
・LLM の責任を上層に集中: 配分判断（KATSURAGI）は決定論で監査可能
・フォールバック禁止: データ取れない時は unknown 返す（欺瞞回避）
・機構造の対称性: 4 機が独立した役割を持ち、KAWORU は他機の落ち穂拾い
・Phase 段階導入: A (重複削除) → B (データ配線) → C (Sonnet スポット)
