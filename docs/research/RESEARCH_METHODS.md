# 領域1：信用性・粉飾検出 ✅

> あなたの設計で**実弾運用で最も致命的なリスク**（D-17：不正企業への投資＝ゼロ化）。
> P2-3信用性ハードフィルタ（❌未）とMELCHIORの反証（B-3）に直撃。
> **3手法とも純粋にコード計算で、LLMを一切使わない＝あなたの原則4と完全合致。**

## 1-1. Beneish M-Score ★最優先・即戦力

**何を検出**：利益操作・粉飾（earnings manipulation）。Enron・WorldCom・Wirecard・Satyam・
康美薬業（Kangmei）を**事前に**検出した実績。「manipulatorは約5倍の確率で後に問題発覚」。

**計算方法（コード・8つの財務比率）**：
```
M = -4.84 + 0.920·DSRI + 0.528·GMI + 0.404·AQI + 0.892·SGI
    + 0.115·DEPI - 0.172·SGAI + 4.679·TATA - 0.327·LVGI
```
各変数（前期比が中心＝2期分の財務データが要る）：
- **DSRI**（売上債権回転）：売掛金が売上より速く伸びていないか（架空売上の兆候）
- **GMI**（粗利率変化）：粗利率の悪化（収益性悪化を隠す動機）
- **AQI**（資産の質）：費用を資産に付け替えていないか（WorldCom型）
- **SGI**（売上成長）：急成長は操作の動機になりやすい
- **DEPI**（減価償却率変化）：償却を緩めて利益を膨らませていないか
- **SGAI**（販管費率変化）
- **TATA**（総発生高/総資産）：利益が現金で裏付けられているか（Enron型）★最重要係数(4.679)
- **LVGI**（レバレッジ変化）

**判定**：M > -1.78（または-2.22、版による）で「操作の疑い」。安全/疑い/高リスクの3ゾーン。

**組み込み先**：
- **P2-3 信用性ハードフィルタ**：M-Scoreが高リスク域→`credibility_flag=warn`（D-14のソフト警戒）。
  ※ハード除外（上場廃止/特設注意）はEDINET由来を先行。M-Scoreは**第2のソフト警戒**に位置づけ。
- **MELCHIORの反証（B-3）**：MELCHIORが「増収率高い→買い」でも、M-Scoreが
  「DSRI高い＝売掛金が売上より速い＝利益の質が怪しい」を**自領域の反証**として摘出。
  → これがB-3反証案の最高の中身。**しかもコード計算なのでR5（LLM創作）の罠が無い**。

**原則適合**：◎ 完全合致。8比率は全てコード計算。LLM不使用。SCORE:NONEとは別物
（M-Scoreは「粉飾の疑い」の専用指標で、3審判の総合スコアではない。混同しない）。

**検証**：◎ 学術裏付け強い。Beneish 1999（Financial Analysts Journal）。
2020追補で「機械学習以外の手法より誤検出率が低い」と実証。Cornell学生が1998にEnronを検出。

**実装難度**：中。**データ要件**：2期分の財務（売掛金/売上/粗利/総資産/固定資産/減価償却/販管費/
営業CF/負債）。あなたのP1-4（yfinance .info）では一部不足。**P1-5（EDGAR/EDINET一次情報）が要る**。

**注意**：①「疑いを統計的に示す」もので**粉飾を証明しない**（誤検出あり）→ ハード除外でなく警戒フラグに。
②金融業・REIT等は会計構造が違い当てはまらない（業種除外が要る）。

## 1-2. Piotroski F-Score（財務健全性の質）

**何を検出**：財務の質・改善傾向（バリュー株が「割安」か「安かろう悪かろう（value trap）」かの選別）。

**計算方法（コード・9項目を0/1で加点、0〜9）**：
- 収益性4点：①ROA>0 ②営業CF>0 ③ROA前年比改善 ④営業CF>純利益（利益の質）
- レバレッジ/流動性3点：⑤長期負債が前年より減 ⑥流動比率が前年より改善 ⑦増資希薄化なし
- 効率3点：⑧粗利率が前年より改善 ⑨総資産回転率が前年より改善

**判定**：7-9＝財務良好、5-6＝可、0-4＝危険（red flag）。
実証：高F-Score株（7-9）は市場をアウトパフォームする傾向（Old School Valueの実測でS&P比優位の年あり）。

**組み込み先**：
- **MELCHIOR**：業績判定の精緻化。現状のMELCHIORは「増収率≥10%かつ営業利益率≥10%でbuy」と
  浅い。F-Scoreを足すと「利益の質・改善傾向」まで見られる。
- **P2スクリーニング**：value trap除外フィルタ。

**原則適合**：◎ 9項目全てコード判定。F-Score自体は「業績の質スコア」でMAGI総合スコアではない。

**検証**：◎ Piotroski 2000（Stanford）。バリュー株での有効性は広く再現。
**注意**：金融・CapEx重い業種では機能しにくい（業種注意）。⑦の増資希薄化チェックは粉飾とも接続。

**実装難度**：小〜中。**データ要件**：2期分の財務（P1-4で大半カバー、一部P1-5）。

## 1-3. Altman Z-Score（倒産確率）

**何を検出**：倒産・財務破綻のリスク。

**計算方法（コード・5比率）**：
```
Z = 1.2A + 1.4B + 3.3C + 0.6D + 1.0E
A=運転資本/総資産  B=利益剰余金/総資産  C=EBIT/総資産
D=株式時価総額/総負債  E=売上/総資産
```
**判定**：Z>2.99 安全、1.81-2.99 グレー、<1.81 危険。

**組み込み先**：P2-3信用性フィルタの補強（倒産リスク警戒）。MELCHIORの反証にも。
**原則適合**：◎ コード計算。**検証**：◎ Altman 1968、半世紀の実績。
**実装難度**：小。**データ要件**：運転資本/利益剰余金/EBIT/時価総額/総負債/売上（大半P1-4）。
**注意**：製造業向けに開発。非製造業・新興国向けの改訂版（Z'/Z''）あり＝**市場/業種で式を分ける**必要。

## 2-A. BALTHASAR（株価）の反証＝テクニカルの「ダマシ（fakeout）」検出

**何を検出**：偽ブレイクアウト・偽シグナル。買いシグナルが出ても「勢いが本物か」を疑う材料。

**プロの実務手法（全てコード判定可・既存technicalsの延長）**：
| 反証材料 | 判定ルール（コード） | 何を意味するか |
|---|---|---|
| **出来高乖離** | ブレイク時の出来高 < 直近10-20本平均の1.5-2倍 | 本物のブレイクは出来高increase。薄商いの突破はダマシ |
| **RSIベアダイバージェンス** | 価格が高値更新 かつ RSIが前高値を更新せず（lower high） | 上昇の燃料が枯れている兆候。ブレイク失敗の前兆 |
| **ATR未達** | ブレイク後3-5本でATR(14)の1倍に届かない | 動きが小さすぎ＝トラップの疑い |
| **リテスト失敗** | 突破後に水準へ戻り、サポート化せず割り込む | 「former resistance→support」が成立しない＝偽 |
| **MA逆行** | 価格はresistance突破だが50日MAが下向き | 短期突破と中期トレンドの不一致 |

**組み込み先**：B-2（BALTHASAR反証・コード）。
現状BALTHASARは golden_cross/macd_bullish で buy、overbought_rsi/death_cross で warn。
**反証として**：buyでも上記（出来高乖離・RSIダイバージェンス・ATR未達）があれば
`counter_within_domain` に「ブレイクの質に疑問」を摘出。

**原則適合**：◎ 全てコード計算。**検証**：△ 実務で広く使われるが学術的厳密性は手法による
（出来高確認・ダイバージェンスは比較的頑健、ATR閾値等はパラメータ依存＝A/B育成の対象）。
**実装難度**：中（OBV/ATR/ダイバージェンス検出の追加）。**データ要件**：出来高・価格系列（P1-2/P1-3で充足）。

## 2-B. MELCHIOR（業績）の反証＝earnings quality red flags（利益の質）

**何を検出**：「増収増益に見えるが、利益の質が低い」兆候。MELCHIORの最大の弱点（現状は増収率・営業利益率のみ）を補う。

**プロの実務手法（コード計算可・段階リスク）**：

> ★Damodaran（NYU）の古典的警告：「**売掛金が売上より速く伸びる**＝売上の質に疑問（channel stuffing）。
> **在庫が売上より速く伸びる**＝売れていない兆候」。

| 反証材料 | 判定ルール（コード） | 段階 |
|---|---|---|
| **CFO/純利益 < 1** | 営業CFが純利益を下回る（特に2四半期連続） | 利益が現金で裏付けられていない（high risk） |
| **DSO悪化** | 売掛金回転日数が売上成長を超えて増加 | 架空売上・channel stuffingの疑い（moderate→high） |
| **在庫 > 売上成長** | 在庫がCOGS/売上より速く伸びる | 滞留・需要鈍化（moderate） |
| **Sloan比率（accruals）** | 利益のうち非現金性発生高の比率が高い・数年上昇 | 利益が将来mean-revert（質低下）。「flag, not verdict」 |
| **GAAP vs 調整後乖離** | 調整後利益がGAAPを継続的に大きく上回る | 「無視してほしい費用」が多い |
| **粗利率の競争説明なき悪化** | 粗利率が前年より悪化＋競争要因の説明なし | 収益性の隠れた劣化 |

**Winvestaのリスク段階分け（credibility_flag設計にそのまま使える）**：
- **safe**：accruals -10〜+10%
- **moderate（要調査）**：CFO/純利益<0.8、DSO業界比悪化、在庫>COGS、stock-based comp>売上15%(tech)
- **high（厳重警戒）**：Beneish M>-2.22、CFO/利益乖離が2四半期連続、監査人交代＋方針変更、粗利率の説明なき悪化
- **critical（投資回避）**：Beneish M>-1.78、限定/不適正監査意見、SEC調査・subpoena、監査人辞任

**組み込み先**：
- **MELCHIOR反証（B-3）**：上記をMELCHIORの `counter_within_domain` に。
  **領域1のBeneish/F-Scoreと統合**（M-ScoreのDSRI/TATA/AQIは、ここのDSO/CFO乖離/資産付替と同じ思想）。
  → **B-3はLLM摘出と書いたが、これらは大半コード計算できる**。LLMに頼らずコードで反証を出せる部分が
    想定より多い＝R5の罠をさらに減らせる。これは設計上の朗報。
- **P2-3信用性フィルタ**：Winvestaの4段階を credibility_flag（ok/warn）の判定基準に。

**原則適合**：◎ 大半コード計算。**検証**：◎ accruals（Sloan 1996）、Damodaranの警告は古典。
**実装難度**：中。**データ要件**：2期分の財務（売掛金/在庫/COGS/CFO/純利益/NOA）→**P1-5一次情報が前提**。

## 2-C. CASPER（文脈）の判定＝センチメント/イベントの方向

**何を検出**：ニュース・イベントが株価にポジ/ネガどちらに効くか。

**現状の実装**：決定論キーワード（_NEG/_POS）＋ P3-7でSonnet解釈（"reads, not counts"）。方向性は固まっている。

**実務手法での補強観点**（深掘りは領域3/4と重なるため要点のみ）：
- **イベントの種類で重要度を変える**（決算/ガイダンス修正/M&A/規制 > 一般ニュース）。topics_collectorの重要度ルールと統合。
- **センチメントは「方向」のみ、数値スコア化しない**（原則：LLMに数値を作らせない）。D-11の定性ラベル。
- **反証（B-3 CASPER）**：ポジ材料が多くても「織り込み済み（株価が既に反応済み）」「一次ソースでない（憶測記事）」を反証として摘出。出典の質（一次/二次）をCASPERの確信度に反映。

**組み込み先**：P3-3/P3-7（既存の延長）。B-3のCASPER反証。
**原則適合**：◎（方向のみ・数値化しない）。**検証**：△（センチメント分析は手法により再現性に幅）。
**実装難度**：中（既存LLM解釈の延長）。**データ要件**：ニュース（A-2で充足済）・出典の一次/二次判定。

## 3-A. V字回復（ターンアラウンド）の定量定義

**核心**：V字＝**業績反転 × 株価底打ち**の合成（spec の定義どおり）。だが「安かろう悪かろう（value trap）」
との区別が最大の難所。**「底にいる」だけでは買わない。「底から反転し始めた」を捉える**。

**実務の定量条件（バックテスト済の自助＝self-help要因）**：
NYC Data Science のターンアラウンド・バックテスト（15+要因検証）の上位5要因：
| 要因 | 定量条件 | 意味 |
|---|---|---|
| **業績が極度に低い水準** | 利益・マージンが極小（底） | 反転余地の前提 |
| **減配/無配** | DPS成長マイナス、無配転落（100%減配）が最高スコア | 経営が痛みを認めた＝膿出し |
| **経営交代** | 減配前後のCEO/COO/CFO交代 | 自助の意思 |
| **オペレーティング・モメンタム回復** | マージンが**直近で**前期比・前年比改善 | ★反転の点火（最重要） |
| **短期信用の安全性** | インタレストカバレッジ・Net Debt/EBITDA の改善 | 倒産せず生き延びる |

**学術的な「反転の点火」指標**：
- **Earnings acceleration（利益成長の加速）**：He & Narayanamoorthy 2019「四半期ごとの利益成長率の変化」が
  将来超過リターンを説明。**単なる増益でなく「増益率が加速しているか」**を見る。V字の本質に近い。
- **Value × Momentum の組み合わせ**：Asness et al. 2013「Value and Momentum Everywhere」。
  Stockopediaの実証「ターンアラウンド＝割安(Value)＋反転の勢い(Momentum)の組み合わせが最も効く」。
  **割安だけ・勢いだけでは負ける。両方揃って初めてV字**。

**株価底打ちの客観基準（Minervini トレンドテンプレートの応用）**：
- 「Stage 1（底ばい）」と「Stage 2（上昇転換）」の区別。
- 例：株価が50日・200日MAの上、200日MAが上向き、52週安値から一定%上、四半期EPS成長が加速。
- **底にいる(Stage1)銘柄は買わず、底から転換した(Stage2)銘柄を買う**。あなたのBALTHASARの判定と統合可能。

**組み込み先**：
- **P2-2スクリーニングのV字4軸**を、上記で具体化：
  ① 業績の底（極小マージン）② **反転の点火**（マージン/EPS成長の加速＝最重要）
  ③ 株価の底打ち転換（Stage1→2）④ 生存性（信用指標改善・倒産しない）
- ②と③が揃って初めて合格。**①だけ（底にいるだけ）は value trap として除外**。
- 領域1のM-Score/F-Score/Z-Scoreを「生存性・質」のフィルタとして④に統合。

**原則適合**：◎ 全てコード計算可。composite は内部用でUI非表示（D-06）。
**検証**：◎ earnings acceleration（学術）・Value×Momentum（Asness）は頑健。self-help要因はバックテスト済。
**実装難度**：中〜大（複数期の財務＋株価ステージ判定）。**データ要件**：複数期財務（P1-5）＋株価履歴（P1-2）。

## 3-B. テーマ戦略の定量検出

**核心**：「どのテーマ（AI/半導体/防衛等）が今いるか」を**相対力（Relative Strength）**で機械検出。
人間が「AIが熱い」と決め打ちするのでなく、データで「資金がどこに流れているか」を捉える。

**実務の定量手法（セクターローテーション）**：
- **相対力ランキング**：各セクター/テーマを 3-6ヶ月の対S&P相対リターンでランク。上位を「リード」。
  Faber/Quantpedia の相対力モデルは1920年代から検証、70%の年でbuy&holdを上回る。
- **3段フィルタ（iQUANT型）**：①RSIで近期モメンタム上位 ②月末価格が9期MA上（トレンド確認）
  ③価格モメンタムで上位選別。**スパイクだけの偽モメンタムを除外**（領域2のダマシ検出と同じ思想）。
- **4象限マップ**：Leading（高モメンタム×高相対力）/ Weakening / Lagging / Improving。
  「Improving（相対力が底から改善）」が**テーマV字**＝あなたの戦略と相性が良い。

**重要な実務的警告（Morningstar 2026）**：
> テーマ投資は「強い超過リターンの時期と、急激な反転(sharp reversals)が交互に来る」。
> ルールベースのモメンタム・テーマ・ローテーションはリスク調整後リターンを改善するが、
> **回転率(turnover)が上がる代償**がある。→ 中期投資のあなたは高回転を避けるべき＝
> テーマ判定は「エントリーの追い風」に使い、頻繁なローテーションはしない。

**組み込み先**：
- **P2-2テーマ4軸**：①テーマの相対力（対S&P 3-6ヶ月）②トレンド確認（MA上・偽スパイク除外）
  ③Improving象限（底から改善）④個別銘柄のテーマ内相対力。
- **CASPER（文脈）と接続**：どのテーマが「なぜ」熱いか（ニュース/マクロ）はCASPERが補完。
  テーマの「方向」は相対力（コード）、「理由」はCASPER（文脈）。役割分担。

**原則適合**：◎ 相対力・モメンタムはコード計算。**検証**：◎ 相対力モデルは長期実証あり。
ただし**テーマ投資自体の反転リスク**は高い→中期・低回転で使う制約が要る。
**実装難度**：中。**データ要件**：セクター/テーマのインデックス or 構成銘柄の価格（要universe設計）。

V字4軸（P2-2）の具体化：

  ② 反転の点火（成長率の加速）★最重要 ← earnings acceleration（学術）

# 領域4：評価・検証の妥当性（バックテストの罠を避ける）✅

> ★最重要の安全弁。領域1〜3でどれだけ良い手法を集めても、**評価が甘ければ「効いている気がするだけ」で
> 実弾を溶かす**。あなたの原則「過信しない・実績で測る」(原則7)とFINSABERの警告の実装。
> P6（評価・学習、丸ごと❌）とC-1（backtester借用）の設計前提。

## 4-A. バックテストの4大バイアス（必ず避ける）

> 「40%年率・Sharpe 2.5の華麗なバックテストが、ライブで損を出す」── これは例外でなく常態。
> 原因は下記の、しばしば不可視なバイアス。

| バイアス | 何が起きるか | あなたの設計での対策 |
|---|---|---|
| **生存者バイアス** | 上場廃止・倒産銘柄を除外したデータで検証→**年率1-4%過大評価**、ドローダウン14%過小評価 | universe に**廃止銘柄も含める**（point-in-time）。今あるNVDA等だけで検証しない |
| **先読みバイアス（look-ahead）** | 決定時点で入手不可の情報を使う（例：当日終値で当日エントリー判定、後で修正された決算値を使う） | **decisionの`data_asof`を厳守**。評価は「その時点で見えていた値」のみ。あなたのR2(時点必須)が既に効く |
| **データスヌーピング** | 同じデータで何度も試行錯誤→テストセットを実質学習。「十分試せば偶然うまくいくものが出る」 | パラメータ調整は**事前に仮説**を立ててから。多数試したら有意水準を上げる（t-stat≥3.0、2.0でなく） |
| **過学習（overfitting）** | パラメータを歴史に最適化しすぎ→ノイズに適合。in-sample優秀・out-of-sample悲惨 | **パラメータ±10%で再検証**（頑健なら性能が近い／過学習なら崖）。少パラメータを保つ |

## 4-B. 正しい検証の手順（実務・学術の合意）

1. **経済的仮説を先に立てる**："なぜこの戦略が効くはずか"を backtest 前に言語化。
   後付けで「効いた理由」を作らない（データスヌーピング防止）。あなたのMAGI各審判は既に
   「業績/株価/文脈」という経済的根拠を持つ＝この点は構造的に守れている。
2. **walk-forward分析**：データを時系列で「過去で組み立て→直後で検証」をローリング。
   ランダム分割は時系列の順序を壊すのでNG。**実運用での更新の仕方を模倣**。
3. **out-of-sample厳守**：戦略構築に使ったデータで評価しない。時間で厳密に分ける。
4. **実コスト織り込み**：スリッページ・流動性・手数料。特に**端株・小型株は約定価格がズレる**
   （あなたの¥1M端株前提＝この影響が大きい。領域外だが要注意）。
5. **Deflated Sharpe Ratio (DSR)**：複数試行・非正規性を補正したSharpe。素のSharpeは選択バイアスで膨らむ。
   Bailey & López de Prado の PBO（Probability of Backtest Overfitting）も。

## 4-C. FINSABER の警告（あなたへの直接の教訓）

FINSABER（KDD'26、https://github.com/waylonli/FINSABER）の実証：
- LLM投資戦略の多くは**狭い期間・少数銘柄での評価で過大評価**されている。
- 長期間・100+銘柄で検証すると**報告された優位が大きく劣化**。
- LLM戦略は「強気相場で保守的すぎ（passiveに負ける）・弱気相場で攻撃的すぎ（大損）」。

→ **あなたへの含意**：MAGIが良い判断をしても、それを「NVDA 1銘柄・数ヶ月」で評価して
「効いている」と結論するのは最も危険な罠。**複数銘柄・複数の市場局面（強気/弱気の両方）**で
評価しないと、実弾で裏切られる。

## 4-D. あなたのP6評価設計への落とし込み

```
P6-1 decision評価ジョブ：
  - 評価は data_asof 厳守（先読み防止）。「その時点で見えていた価格」で actual_return。
  - 評価期日が来るまで pending（前倒し評価しない＝spec P6-1に既にある。正しい）。

P6-2 Track Record：
  - S&P比超過を必ず併記（StockBench：多くのLLMがbuy&holdに負ける）。
  - 「短期間・少数銘柄の好成績」を過信表示しない。最低サンプル数（例：30 decision以上）まで
    「暫定」と明示（FINSABER）。
  - 強気/弱気の両局面の成績を分けて見せる（FINSABERの「局面で偏る」警告）。

P6-3 A/B育成：
  - パラメータ調整は事前仮説→walk-forward→±10%頑健性チェック。
  - 多数の変種を試したら有意水準を上げる（t-stat≥3）。Deflated Sharpe で選択バイアス補正。
  - 「人間がGitで勝者を選ぶ」枠は維持（原則7）。ただし選ぶ基準を上記で厳格化。

C-1 backtester借用（ai-hedge-fund）：
  - 指標計算は借りるが、**生存者バイアス対策（廃止銘柄を含むuniverse）を自前で足す**。
    借用元がsurvivorship-freeとは限らない＝C-0で要確認。
```

## 領域4のまとめ（評価の安全弁）

# 【第2波】検証・リスク・派生手法

> 第1波（手法の発見）に対し、第2波は「**本当に効くか・どこで壊れるか・より良い亜種はあるか**」。
> 各領域の主力手法を、最新の批判研究・誤検出率・派生版で検証する。

## 領域1 検証：信用性・粉飾検出

### 1-V1. Beneish M-Score の実力（数字で）
- **検出力 約76% / 誤検出率 約17%**（Beneish原典のホールドアウト検証）。
  → **万能ではない**。4社に1社の操作を見逃し、6社に1社を誤って疑う。
  → **設計含意**：ハード除外でなく**警戒フラグ（warn）に留める**第1波の判断は正しい。確定済。
- 閾値 -1.78 は「見逃しコスト:誤検出コスト = 20:1〜30:1」を前提に最適化された値。
  あなたは実弾運用で見逃し（粉飾企業を買う）のコストが極端に高い→ **閾値を厳しめ(-1.78)に**設定し、
  warnを多めに出す方が、あなたの損失構造に合う。

### 1-V2. ★重大なリスク：手法間の不一致
- **M-Score と Z-Score の判断一致率は約30%**（Borsa Istanbul研究、Özari et al. 2025）。
  → 2手法は**別物を見ている**（M=利益操作、Z=倒産確率）。一致しないのは当然だが、
    「両方 green だから安全」とは言えない。**それぞれ別の警戒として独立に扱う**べき。
- **Comscore事例**：M-Scoreが粉飾を検出できず、Z-Scoreの方が予測力が高かった反例
  （strathmore研究）。→ **単一指標を信用しない**。複数を独立フラグとして並べる
  ＝あなたのMAGI思想（合意を信じない・割れを見せる）と整合。**信用性も「3審判」的に複数指標で**。
- **Altman Z-Scoreの経年劣化**：Grice & Ingram (2001)「近年の精度はAltman原典より有意に低い」。
  → 古い係数をそのまま使わない。製造業/非製造業/新興国で式を分ける（Z/Z'/Z''）。

### 1-V3. 派生・改良手法（第1波になかったもの）
| 派生 | 内容 | あなたへの価値 |
|---|---|---|
| **Dechow F-Score** | Beneishの後継。発生高の質に焦点。Adani等の検証に使用 | M-Scoreの補完。会計操作の別角度 |
| **係数フリー版（Random Forest）** | M/Zの**8+5変数を特徴量にし、固定係数を捨ててML分類**。Borsa Istanbulで精度向上 | ★原則注意：MLは「数値を出す」が**解釈可能性が落ちる**。あなたの「なぜ警戒か」を説明する設計と相性悪い。**変数は使うが係数フリーML分類は採らない**のが筋（コードで説明可能な閾値判定を維持） |
| **Piotroski F + M-Score 併用** | 質スコアと操作スコアの2軸 | 第1波の組み込み方針（F=質、M=操作）が学術的に支持される |

### 1-V4. 日本株での注意（あなたはJP対象）

  閾値を現地調整した研究多数）。日本のGAAP/IFRS差、会計慣行で原典の閾値がズレる可能性。
- G7研究では「manipulatorは現金保有が多い（米英加仏伊）が**日独では当てはまらない**」。
  → **日本株はM-Scoreの閾値・解釈を米国そのままで使わない**。当面は警戒フラグの「参考」に留め、
    EDINET由来のハード情報（監査意見/GC注記）を主にする（D-14の段階導入と整合）。

### 領域1 検証まとめ

### 2-V1. ★最重要リスク：ファクター劣化（alpha decay）

## 領域3 検証：スクリーニング（V字・テーマ）

### 3-V1. ★テーマ投資の罠（数字で確定）
- **Ben-David, Franzoni, Kim, Moussawi (2022)**：テーマETFは**平均して市場に劣後**。
  特化型ETFは**launch後5年でリスク調整後価値の約30%を失う**。原因は手数料でなく**割高**。
- **メカニズム**：テーマ特定→商品化の間に、対象銘柄が既に割高化。**興味のピークでlaunchされる**。
  「providerは投資家の外挿的期待に迎合し、注目テーマを商品化する」。
- **AIテーマの実証**（Colloredo-Mansfeld 2025）：AI ETF構成236銘柄の月次alpha中央値は**0.0007（≒0）**。
  「AI株は平均してリスクに見合うリターンを出していない＝市場効率の勝利」。

→ **設計含意（あなたのテーマ戦略への直撃）**：
  1. **「話題のテーマを追う」は構造的に負ける**。テーマが話題になった時点で割高。
  2. 第1波で挙げた「Improving象限（底から改善）」を狙う方針は、この罠を回避する正しい方向
     ＝**まだ話題でない・底から改善し始めたテーマ**を捉える。話題のピーク（Leading象限の過熱）は避ける。
  3. テーマは「銘柄選択の追い風」に留め、テーマ自体に賭けない。**個別銘柄のV字が主、テーマは従**。
     → spec の「V字4軸 ＋ テーマ4軸 → composite」で、**V字を主に重み付け**すべき。

### 3-V2. ★ターンアラウンドの罠：value trap
- **本質的な問い方の転換**：「How cheap is this?（どれだけ安いか）」でなく
  **「Why is this so cheap?（なぜ安いか）」**。安いだけの株は、構造的衰退の罠。
- **value trapの実態**：「衰退市場で今は現金を生むが、コア市場が縮小し、いずれ何も残らない」。
  プロは「来ないかもしれないturnaroundを何年も待つより、損切りして優良企業に資本を移す」。
- **回避法（Research Affiliates / Columbia Threadneedle）**：
  - **質（quality）と モメンタムでスクリーン**：「最悪のモメンタムのvalue株を避ける」。
    → 第1波の「Value×Momentum両立」「①底だけでは買わない」が学術的に支持される。
  - **業界の見通し・参入障壁・ブランド・現金創出力**を見る（単なる割安比率でない）。
  - **経営の文化・ビジョン**（turnaround成否の最深要因）。「culture eats strategy for breakfast」。

→ **設計含意**：
  - MELCHIORのV字判定に「**Why cheap**」の質チェックを必須化（領域1のF-Score/質指標と統合）。
  - CASPER（文脈）が「業界の見通し・なぜ安いか」を補完。**V字は MELCHIOR単独でなく
    MELCHIOR（業績の底と反転）× CASPER（なぜ・業界）× BALTHASAR（株価の転換確認）の合議**で
    判定すべき。3審判が揃って初めてV字＝あなたのMAGI構造がvalue trap回避に効く。

### 3-V3. 派生：genuine recovery の見分け方
- Columbia Threadneedleの実務スクリーン（genuine recovery vs value trap）：
  ①強い財務トラックレコード ②過去の高リターン実績 ③健全なBS ④株価が長期平均比で統計的に過小
  ＋ ⑤四半期利益のトレンドと反転シグナル。
  → 「**かつて優良だったが一時的に落ちた**」を狙う（構造衰退でなく一時的不振）。
  これは「ゾンビ低位株のV字」と「優良株の一時調整のV字」を区別する基準。**後者を狙う**。

### 領域3 検証まとめ
```
テーマの罠：話題化＝割高＝負け。Improving象限（底から改善・未話題）を狙う。テーマは従、V字が主
value trapの罠：「How cheap」でなく「Why cheap」。質×モメンタムで衰退株を除外

```

# 【第2波】統合結論 ── 検証で見えた本質

## 全領域に共通した「効きすぎる手法ほど壊れる」構造
第2波で4領域すべてに共通したのは、**「検証済み・有名な手法ほど、発表・普及後に効果が劣化する」**
という冷酷な構造。
- M-Score：76%検出/17%誤検出（万能でない）
- ファクター：alpha半減（McLean-Pontiff）、モメンタム10%→2%
- テーマ：launch後5年で30%価値喪失
- value：「How cheap」の罠

これは**あなたの不変原則「過信しない・混入前提で検出」「複数の独立検証」が正しかった**ことの、
さらに強い裏付け。第1波で「原則は学術と整合」と書いたが、第2波は一段進めて
**「原則こそが、手法の劣化・罠への唯一の保険」**だと示した。

## 検証が確定させた設計判断（5つ）
1. **信用性は単一スコアでなく複数独立フラグ**（M/F/Z は別物を見る・一致率30%）。MAGI思想を信用性にも適用。
2. **すべての手法を warn 止まり＋A/B継続監視**（ハード判定にしない）。誤検出とファクター劣化があるため。
3. **テーマは従・V字が主**。話題テーマは構造的に割高＝負け。未話題のImproving象限を狙う。
4. **V字は3審判合議でvalue trap回避**（業績の底×反転、なぜ安い、株価転換）。単一審判で判定しない。
5. **LLMにデータ汚染リスクあり→評価は訓練カットオフ以降・数値はコード堅持**。あなたの構造が防御。

## ★最大の戦略的含意
あなたのシステムの**競争優位は「より良い手法を持つこと」ではない**。
有名手法は誰でも使え、使われるほど劣化する（factor crowding）。
あなたの優位は**①複数独立視点（MAGI）②人間決裁＋中期低回転 ③数値はコード（LLM汚染防御）④過信しない構造**。
つまり**「手法の優劣」でなく「手法が壊れても破綻しない構造」で勝つ**。
→ リサーチした手法（M-Score等）は導入するが、**どれも単独では信用せず、構造（MAGI＋人間＋低回転）で
受け止める**。これが第2波の最終結論。手法は弾、構造が銃。弾は劣化するが銃は残る。
