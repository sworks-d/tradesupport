1. システム全体図

図の読み方： ① → ⑦ の順に上から下へ流れる。↓ が主フロー、← が注入元（LLM Layer など脇から差し込まれる要素）。 左列＝ZEELE 車線（紫破線・草案）は探索・発議のみ。決裁ラインへ直結せず、④MAGI 判定をバイパスして⑥UI（ZEELE zone）で表示される。 右列＝MAGI 車線（実線）はデータ→MCP→提案→MAGI 4段→碇司令→UI→人間決裁の本流。SCORE: NONE / 数値はコードのみ / LLMは「読む」だけ。 ⑥UI で2車線が左右2ゾーンに合流し、中央に「watchlist 昇格」ボタン。これが ZEELE↔MAGI 唯一の橋で、押すと翌朝バッチで③MAGI ラインに注入される。 ZEELE は docs/plan/DECISIONS.md 未反映の草案（§7参照）。確定までは UI でも視覚分離で表示する。

7. アーキテクチャ拡張案：二車線設計 ZEELE × MAGI ＋ 北極星 claude-trading-skills

2026-05-26 更新（D-24 確定）： 設計北極星を tradermonty/claude-trading-skills（MIT）に確定。 stock_skills は守り系モジュール提供源に格下げ。詳細仕様 = docs/plan/spec/X2_claude_trading_skills_adoption.md。 二車線設計（ZEELE × MAGI）は引き続き草案だが、MAGI 車線の "規律監督OS" の中身は X-2 で実装スペック化済。§7.6 参照。
ZEELE 側は引き続き草案。 着手は B0〜B6（MAGI本体）がペーパー運用に乗ってから（その間は MAGI車線への先行取り込みのみ実施）。

7.1 背景：現状の哲学的緊張

SCORE: NONE 原則は決裁直前のハルシネーション遮断のため。「攻め架構を凍結」の結論は取引執行のエッジ無しに対するもの。両者を一本化したことで探索/発見にすら予測・スコアを禁じる形になり、入口が痩せている。車線分離でこの矛盾を解く（Evangelion メタファ：ZEELE＝シナリオ発議、MAGI＝独立検証の合議体）。

7.2 構造：三層（探索データ → ZEELE / 真実データ → MAGI、車線間のゲートは人間のみ）

source_refs（出典）必須・data_asof（時点）必須 重要数値は2ソース照合 ZEELE車線（発議・探索） stock_skills 攻め系を移植 — 16プリセット / momentum / contrarian / alpha / market-research（Grok narrative） LLM数値 OK スコア・予測・シナリオ歓迎 出力＝候補プール＋物語 「参考／未照合」バッジ常時表示 サンセット条項 6ヶ月毎に ZEELE発議銘柄の1年後リターン vs ベンチマーク評価。 勝てなければ車線ごと廃止（凍結思想の裏口復活を防ぐ）。 MAGI車線（判断・決裁） 3審判（独立検証）→ 防御層 → 統合機構 → 碇司令 → 人間決裁 stock_skills 守り系を移植（来歴メタ必須コントラクトへ） SCORE: NONE 数値はコードのみ／LLM非生成 出力＝決裁可能な推奨 買い／売り／保留＋出典＋時点 先行取り込み（B並走中に着手可能） 複利シミュ／株主還元利回り（配当＋自社株買い）／ health_check＋調整アドバイザー17ルール 人間が watchlist へ昇格 ── 車線間の唯一の橋 ZEELE→decisions の直接FK禁止／MAGIプロンプトに ZEELE 出力を入力しない（独立性原則） → 既存§1の「朝バッチ起動 → 3審判 → 防御層 → 統合 → 碇 → 人間決裁 → 手動発注」フローに合流 候補プール 朝バッチでMAGI判定

8.5 KAWORU の「いいとこどり」ロジック

KAWORU は 3 機（REI/ASUKA/SHINJI）が 共通で保有している銘柄を最優先で買い付ける：

def _consensus_tickers(engine, peers=("REI", "ASUKA", "SHINJI")) -> set[str]:
    """3 機が全員 active 保有している ticker の集合を返す。"""
    return set.intersection(
        *(set of tickers held by each peer)
    )

# KAWORU の fill 順序を consensus 優先でソート
if personality.name == "KAWORU":
    consensus = _consensus_tickers(engine)
    decisions = sorted(decisions,
        key=lambda d: 0 if d.ticker in consensus else 1)

合議シグナル（皆が買う = 強い）を盗み、加えて 3 機が見ない「静観」も独自眼で組み入れる。 検証データの多様性を最大化する 異形枠。

8.6 動的 max_position_pct（PnL 連動）

各機の 1 銘柄上限は累積 PnL に応じて自動調整される（勝ってる時は強気・負けてる時は守り）：

累積 PnL調整意図
+5% 超max × 1.2（上限 30%）↑強気モード：勝てる場面で集中
-5% 〜 +5%標準判定不能領域・基準値
-5% 未満max × 0.8↓守りモード：負け方を制限
