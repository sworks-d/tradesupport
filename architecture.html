🎖 katsuragi_dispatch 内部（A+：DS-first / AKAGI-verify）

選定者(DS)と検証者(AKAGI)を分離。DS が先に自分の信号で提案 → AKAGI の重い検証は 提案された銘柄だけに走る → KATSURAGI が採用を決める。これでゲート⑥の実績を DS の選定能力に帰属できる（AKAGI が選定に混ざる循環を避ける）。
1
HALT / 予算（treasury available・G-7 逓減・1 命令上限 ¥500k）
2
候補プール = MAGI awaiting ∪ ZEELE active 上位 5（+ live は補完 Universe）。source: magi / zeele / both
3
DS 4 機が先に自発 proposal（AKAGI 非依存）: REI/ASUKA/SHINJI=select_from_pool（preset/stance/score）、 KAWORU=select_kaworu_contrarian（軽量 RSI のみ＝fetch_technicals_lite。業界/ニュースは選定に使わない）
4
AKAGI(ritsuko) が提案された銘柄だけを検証: TickerBrief 5 中立スコア（news LLM / industry / peer / event / deep）+ 市場 regime
5
MISATO（DS 司令塔）: AKAGI brief で priority 計算 + 例外ブロック（決算/ピア劣位/Sonnet 強売り）+ 排他制御（同銘柄=priority 最高の 1 機）
6
opportunity_fill: priority 降順 greedy + 4 ガードレール（1 銘柄/source/sector/1 機上限）+ cash_floor 40%
7
→ DispatchPlan（assignment: ticker→pilot, picked）。Decision に pilot / horizon / stop / preset を反映。 fill は picked のみ（paper_fill_approved(allowed_tickers=picked) で plan 外 fill を物理遮断）
原則 1 Decision → 1 機 → 1 Portfolio（排他割当）。重複回避であって 1 機 1 銘柄ではない（1 機は予算内で複数保有可）。 integrity I7 で「1 decision_id に Portfolio 複数（active+closed）」を検出。

📏 計測 → 増額ゲート⑥ 層（「勝てるか」の客観判定・本セッション構築）

A
fill 時（auto_fill_paper / mark_filled / notify / paper_fill_approved）に stamp_evaluation_fields： stop / target / 評価期日 / entry_market_regime を刻む。Portfolio.decision_id で紐付け
B
保有 → 退出: paper_close_due が stop/time で閉じる時、実退出損益を buy Decision に記録 （horizon 価格で上書きしない＝守り主導の測定正確性）
C
evaluate_due_decisions（07:30）: 期日到来分を採点。TOPIX 保有期間 benchmark で対ベンチ超過、 往復コスト 0.44% 控除で コスト後α を算出
D
official_gate_evaluation: 公式部分集合（entry_market_regime 有＝正規 fill 由来・legacy 除外）に対し 下表 6 要件をまとめて一意判定。report / 昇格 / UI はこの関数だけ参照（scripts/check_gate.py で表示）
要件（増額ゲート⑥ + コスト後α）閾値（risk/params 正本）
評価件数 n≥ 30
命中率 hit_rate≥ 50%
平均 R（R-mult）≥ +0.5
最大 DD（評価列 proxy）≤ 15%（実口座 DD は正式判定前に置換予定）
コスト後α（対 TOPIX 超過）> 0 かつ 全件 benchmark 有（部分欠損は誤通過防止のため fail）
両局面通過順境 + 逆境 両方で entry 実績（※単日 regime proxy・A8 で trailing 化予定）
勝ち定義 = ゲート⑥（6 要件すべて）＋ コスト後α>0。 通過するまで実弾を増額しない（tier 段階移行の門）。 現状: 公式評価 n=0（フォワード実績はこれから蓄積）。 バックテストは規律の事前足切りであって勝率証明ではない（PIT 財務欠如・survivorship のため）。
※ 公式集合は現状「A3 後の正規 fill 全般」。DS 単一フロー専用の識別（source/filled_via 列）は A7 で追加予定。

  優先 1: WILLE_MAX_LOT_JPY が設定されていればその金額（直接指定）

  localStorage で永続化、refresh/execute API に自動送信

7.1 背景：現状の哲学的緊張

SCORE: NONE 原則は決裁直前のハルシネーション遮断のため。「攻め架構を凍結」の結論は取引執行のエッジ無しに対するもの。両者を一本化したことで探索/発見にすら予測・スコアを禁じる形になり、入口が痩せている。車線分離でこの矛盾を解く（Evangelion メタファ：ZEELE＝シナリオ発議、MAGI＝独立検証の合議体）。

7.2 構造：三層（探索データ → ZEELE / 真実データ → MAGI、車線間のゲートは人間のみ）

source_refs（出典）必須・data_asof（時点）必須 重要数値は2ソース照合 ZEELE車線（発議・探索） stock_skills 攻め系を移植 — 16プリセット / momentum / contrarian / alpha / market-research（Grok narrative） LLM数値 OK スコア・予測・シナリオ歓迎 出力＝候補プール＋物語 「参考／未照合」バッジ常時表示 サンセット条項 6ヶ月毎に ZEELE発議銘柄の1年後リターン vs ベンチマーク評価。 勝てなければ車線ごと廃止（凍結思想の裏口復活を防ぐ）。 MAGI車線（判断・決裁） 3審判（独立検証）→ 防御層 → 統合機構 → 碇司令 → 人間決裁 stock_skills 守り系を移植（来歴メタ必須コントラクトへ） SCORE: NONE 数値はコードのみ／LLM非生成 出力＝決裁可能な推奨 買い／売り／保留＋出典＋時点 先行取り込み（B並走中に着手可能） 複利シミュ／株主還元利回り（配当＋自社株買い）／ health_check＋調整アドバイザー17ルール 人間が watchlist へ昇格 ── 車線間の唯一の橋 ZEELE→decisions の直接FK禁止／MAGIプロンプトに ZEELE 出力を入力しない（独立性原則） → 既存§1の「朝バッチ起動 → 3審判 → 防御層 → 統合 → 碇 → 人間決裁 → 手動発注」フローに合流 候補プール 朝バッチでMAGI判定
図の読み方： 紫＝ZEELE車線（発議・探索）／青＝MAGI車線（判断・決裁）／オレンジ＝既存の真実データ経路。 ZEELE と MAGI は 直接接続せず、watchlist（黄色：人間ゲート）でのみ繋がる。 既存§1の全フローは「真実データ → MAGI車線」側にそのまま生きる。

7.4 漏出防止の規律（UIで強制、良心ではなく構造で）

  1. UI色分け＋ラベル：ZEELE出力は別ゾーン・別配色・「参考／未照合」バッジ常時。new_dashboard.html の現行レイアウトには侵入せず、新規セクションで追加。
  2. 物理的な経路遮断：ZEELE出力テーブルから decisions テーブルへの直接FKを禁止。watchlist 経由でのみ流入（コードで強制）。
  3. MAGIプロンプト独立性：MAGIプロンプトに ZEELE 出力（スコア・見通し）を入力しない。審判の独立性原則の延長。
  4. サンセット条項：6ヶ月毎に ZEELE発議銘柄の1年後リターン vs ベンチマーク評価。勝てなければ ZEELE 車線ごと廃止。
  5. 用語衝突の整理：「scenario」は ZEELE（narrative_scenario：LLM生成）と MAGI（stress_scenario：コード由来）で命名規約を分ける。

8.5 KAWORU の「いいとこどり」ロジック

KAWORU は 3 機（REI/ASUKA/SHINJI）が 共通で保有している銘柄を最優先で買い付ける：

def _consensus_tickers(engine, peers=("REI", "ASUKA", "SHINJI")) -> set[str]:
    """3 機が全員 active 保有している ticker の集合を返す。"""
    return set.intersection(
        *(set of tickers held by each peer)
    )

# KAWORU の fill 順序を consensus 優先でソート
if personality.name == "KAWORU":
    consensus = _consensus_tickers(engine)
    decisions = sorted(decisions,
        key=lambda d: 0 if d.ticker in consensus else 1)

合議シグナル（皆が買う = 強い）を盗み、加えて 3 機が見ない「静観」も独自眼で組み入れる。 検証データの多様性を最大化する 異形枠。

8.6 動的 max_position_pct（PnL 連動）

各機の 1 銘柄上限は累積 PnL に応じて自動調整される（勝ってる時は強気・負けてる時は守り）：

累積 PnL調整意図
+5% 超max × 1.2（上限 30%）↑強気モード：勝てる場面で集中
-5% 〜 +5%標準判定不能領域・基準値
-5% 未満max × 0.8↓守りモード：負け方を制限
